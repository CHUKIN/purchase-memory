## Как собирать приложение для Render (отложено 06.10.2026)

Сейчас образ собирается на Mac (`scripts/publish-image.sh`), выкладывается в
закрытый GHCR, в Render — ручной **Manual Deploy**. Владелец решил пока
оставить так ради контроля.

Без Docker на Render нельзя: для .NET у Render нет готовой среды, только
Docker. Скорость работы приложения от способа сборки не зависит. Меняется
только удобство выкладки.

Варианты на потом (когда код будет в git):

1. **Render собирает из репозитория** по `Dockerfile`: `git push` → сборка
   5–10 минут на стороне Render → выкладка. Автодеплой можно включить только
   для `main` или оставить ручную кнопку. Убирает GHCR, токен `read:packages`
   и скрипт публикации. Минусы: на бесплатном тарифе минуты сборки
   ограничены, `Dockerfile` надо проверить на нативную сборку `amd64`.
2. **GitHub Actions собирает образ и прогоняет тесты**, Render забирает
   готовый. Сломанная сборка не доедет до Render. Настраивается дольше.

## Варианты одного товара: вкус, жирность, без лактозы (отложено 07.10.2026)

Пример: «ACTIV KEFI NAT 280» и «ACTIV KEFI BOR 280» — один продукт, разные
вкусы. Сейчас вариантов нет: сопоставление сливает строки в один товар
(общая история цен, алиас на будущие чеки этого магазина). Пока правило:
разные вкус/объём/жирность — «Создать новый товар»; объединять через бренд,
категорию и теги.

Идея на подумать: товар-«семейство» с вариантами под ним — общая история
цен с разбивкой по вариантам. Вернуться, если тегов окажется мало.
