# Теги товаров (3 октября 2026)

Требования — раздел «Категории и теги» в `ПРОДУКТОВАЯ_СЕССИЯ.md`: у товара одна
основная категория для устойчивых итогов и сколько угодно тегов household для
пересекающихся срезов («для ребёнка», «к празднику», «акция», «веган»). Новые
теги создаёт только человек. Продолжение `РЕЗУЛЬТАТЫ_КАТЕГОРИИ_И_БРЕНД.md` и
`РЕЗУЛЬТАТЫ_ФИЛЬТРЫ.md`.

## Что сделано

### Данные

- Новая таблица `product_tags`: имя (до 40 символов, пробелы по краям
  убираются, двойные схлопываются), `NormalizedName` для уникальности, время
  создания и изменения. Цвета нет — это не нужно для первой версии.
- Уникальность — по нормализованному имени, тем же `ProductNameNormalizer`,
  что и у бренда: регистр, лишние пробелы и польские буквы не учитываются.
  «Акция» и «акция», «Łódź» и «lodz» — один тег. Проверяет сервис, а
  уникальный индекс в базе подстраховывает от двух одновременных запросов.
  Имя без единой буквы или цифры («!!!») не принимается.
- Новая таблица `product_tag_links` (товар ↔ тег, ключ — пара). У товара не
  больше 20 тегов. При удалении товара или тега связи удаляются каскадом.
- Теги принадлежат **товару**, а не строке чека и не покупке, поэтому тег
  действует на все прошлые и будущие покупки товара (как категория).
- Список тегов и теги товара упорядочены по алфавиту (по нормализованному
  имени, сортировка в .NET), поэтому SQLite и Postgres показывают одинаково.

### Журнал изменений

- Изменение тегов товара пишется в тот же журнал товара
  (`product_audit_entries`, поле `tags`): было → стало, имена через запятую,
  «—» — тегов не было. Если набор не изменился, запись не создаётся.
- Удаление тега пишет каждому затронутому товару запись с источником
  `tagDeleted` («акция, веган» → «веган»).
- Переименование тега в журнал товаров не пишется: это изменение подписи
  сразу везде, а не решение по конкретному товару.

### API

Все новые маршруты защищены той же политикой «одобренный пользователь»:

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/tags` | теги по алфавиту с числом товаров `[{id, name, productCount}]` |
| POST | `/api/tags` | `{name}` — новый тег; повтор — 409, пустое/длинное имя — 400 |
| PUT | `/api/tags/{id}` | `{name}` — переименование; занятое имя — 409, нет тега — 404 |
| DELETE | `/api/tags/{id}` | удаление тега и его связей; товары остаются; ответ `{tagId, unlinkedProductCount}` |
| PUT | `/api/products/{id}/tags` | `{tagIds: [...]}` — полная замена тегов товара; неизвестный тег в теле — 400, нет товара — 404, больше 20 — 400 |
| GET | `/api/products?tagId=…` | фильтр каталога по тегу |
| GET | `/api/purchases?tagId=…` | фильтр ленты по тегу |

- `GET /api/products` и `GET /api/products/{id}` возвращают `tags: [{id, name}]`.
- Фильтр `tagId` можно повторить (`?tagId=a&tagId=b`): тогда нужны **все**
  перечисленные теги. Интерфейс пока передаёт один.
- Фильтр тега складывается с категорией, «Без категории», брендом, поиском,
  датами и статусом (И). В ленте покупка подходит, если хотя бы одна её строка
  связана с товаром, у которого есть тег; у строк заполняется `matchesFilter`
  точно так же, как для категории и бренда.
- Неизвестный тег в фильтре — 400 (как неизвестная категория), не-GUID — 400,
  пустое `?tagId=` — фильтра нет.
- Журнал `GET /api/products/{id}/audit` теперь содержит и записи о тегах
  (`fieldName: "tags"`, `source: "human" | "tagDeleted"`).

### Код

- Domain: `ProductTag`, `ProductTagLink` (`ProductTag.cs`), в
  `ProductAuditEntry` — поле `tags` и источник `TagDeleted`.
- Application: `Products/Tags/` — `IProductTagService`/`ProductTagService`,
  `IProductTagRepository`, исключения `ProductTagNotFoundException`,
  `ProductTagConflictException`. Фильтр тега добавлен в общий
  `ProductClassificationFilter.ResolveAsync`, поэтому каталог, лента и MCP
  проверяют его одинаково.
- Infrastructure: `ProductTagRepository`; в `SqliteProductCatalogRepository`
  каждый выбранный тег сужает выборку подзапросом `EXISTS`. Одновременное
  изменение (тот же тег создан дважды, связь с только что удалённым тегом)
  превращается в 409, а не в 500.
- API: `TagEndpoints.cs`; `ProductEndpoints`/`PurchaseEndpoints` принимают
  `tagId`.

### MCP

- Новый read-only `list_tags` (как `list_brands`): теги с числом товаров.
- `search_purchases` и `search_products` получили необязательный `tagId`;
  в результатах `search_products` есть `tags` (имена).
- В инструкции MCP-сервера упомянуты `list_brands` и `list_tags`.

### Интерфейс

- Карточка товара: блок «Теги» — чипы (с «#», чтобы не путать с категорией),
  кнопка «Изменить теги». В режиме правки все теги household показаны
  кнопками-переключателями (`aria-pressed`, работают с клавиатуры и
  скринридера), счётчик «выбрано N из 20», поле «Новый тег» и кнопка «Создать
  тег» — созданный тег сразу отмечается. «Сохранить» / «Отмена». Если
  набрать имя уже существующего тега, он просто отмечается — сравнение без
  учёта регистра, пробелов и польских букв, как на сервере («lodz» отметит
  «Łódź», `features/tags/tagKey.ts`). Если сервер всё же ответил 409 —
  понятное сообщение «Такой тег уже есть». Если список тегов не загрузился,
  на странице товара видно «Не удалось загрузить теги.», а текущие теги
  товара остаются видны без правки. Рядом ссылка
  «Как это работает» на новую тему подсказок.
- Под карточкой — ссылки «Покупки с тегом «…»» для каждого тега.
- Каталог «Товары»: теги видны чипами в карточках списка; фильтр «Тег» рядом
  с «Категория» и «Бренд» (нативный `<select>`, «Все теги» + список). Поле
  появляется, когда есть хотя бы один тег.
- «История покупок»: тот же фильтр «Тег». Строка «Подходит: …» работает и для
  тега.
- Фильтр хранится в адресе (`tag`), сбрасывается «Сбросить фильтры» (лента) и
  «Сбросить поиск» (каталог). Тег из ссылки, которого больше нет, молча
  сбрасывается на «Все теги». В отличие от категории, лишнего запроса с 400
  при этом нет: при теге в ссылке список подождёт загрузки тегов. Если список
  тегов не загрузился вовсе, тег из ссылки не отправляется (иначе устаревший
  тег превратил бы страницу в ошибку).
- «Управление тегами» внизу страницы «Товары» (свёрнуто, рядом с
  «Управление категориями», тот же вид): добавить, переименовать на месте,
  удалить в два шага, число товаров у каждого тега.
- На телефоне (375 px) горизонтального скролла нет, переключатели — крупные
  (высота 40 px). На широком экране три фильтра стоят в ряд, на среднем тег
  переносится на свою строку.
- Переводы ru и en (`tags.*`, `filters.purchasesWithTag`).
- Stories: `Purchase Memory/Tags/ProductTags` (с тегами, без тегов, правка,
  первый тег, телефон en, менеджер, менеджер на телефоне) и новые варианты
  `Products/Card` — `WithTagsMobileRu`, `ReadOnlyTagsDesktopEn`.

## Миграции

- SQLite: `20261003172136_AddProductTags`; Postgres:
  `20261003172138_AddProductTags` (схема `purchase_memory`).
- Только две новые таблицы и индексы; существующие данные не трогаются.
  Снимки моделей изменились только добавлением этих двух сущностей.

  во временной папке агента; фабрика сразу удалена.

- Ошибка загрузки списка тегов на странице товара больше не прячет блок

- Повторная проверка нашла расхождение с сервером в границе «цифра/буква»
  (`a1b`): исправлено в `tagKey.ts`, добавлены проверки. Повторное review —
  готово; tsc чисто, vitest 198/198, сборка wwwroot успешна.

## Известные ограничения

- В интерфейсе фильтр — один тег; несколько тегов (все сразу) доступны только
  через API/MCP.
- Аналитика и «Нужно проверить» тег не учитывают (следующий шаг).
- AI теги не предлагает (по решению — только существующие теги и только
  позже).
- Массовой расстановки тегов из каталога нет — только на карточке товара.
- Тег, созданный в редакторе карточки, остаётся в списке, даже если нажать
  «Отмена» (его можно удалить в «Управление тегами»).
- Лента по-прежнему смотрит только 1000 последних покупок.
- Журнал товара пока виден только через API (`/api/products/{id}/audit`),
  экрана для него нет — как и раньше.

## Для подсказок

- У товара одна категория, а тегов — сколько угодно: «для ребёнка», «к
  празднику», «акция», «веган».
- На странице товара в блоке «Теги» нажмите «Изменить теги», затем нажимайте
  на теги, чтобы добавить или убрать. Нового тега нет — введите его в «Новый
  тег» и нажмите «Создать тег». В конце — «Сохранить».
- Переименовать или удалить тег — «Управление тегами» внизу страницы «Товары».
  Удалённый тег пропадает у всех товаров, товары и покупки остаются.
- «Акция» и «акция» — один тег: регистр, лишние пробелы и польские буквы не
  учитываются. Тег — до 40 символов, у товара — до 20 тегов.
- В «Истории покупок» и «Товарах» есть фильтр «Тег»; он складывается с
  категорией, брендом, поиском и датами. На странице товара — ссылка
  «Покупки с тегом «…»».
- Теги создаёт только человек, приложение само их не расставляет.

## Следующий кандидатный шаг

Фильтр по тегу (и по категории/бренду) в аналитике и «Нужно проверить»; затем,
при желании, подсказки AI из уже существующих тегов.
