# Results: receipt line carousel («Карусель строк чека»)

Status: implemented 2026-10-20; independent review READY with minor defects, all fixed (follow-up below), awaiting re-review. Level: Обычный (frontend only, no backend change, no migrations).

## What was done
- New `LineCarousel` (`src/PurchaseMemory.Web/src/features/line-review/LineCarousel.tsx`), per the owner-approved mock: totals status line (lines vs receipt total, green when it adds up, otherwise "short/over by"), 230 px receipt photo that moves to the current line with the stage-1.3 combo highlight (reuses `LinePhoto`/`TextHighlight`, whole-photo fallback for no box / multi-photo, pinch/double-tap/zoom button), prev/next chevrons (44 px, aria-labels), «Строка N из M» + dots (tap to jump; current wide dark green, problem orange, checked green; at most 8 dots of 24 px, the window slides), line card editable in place (Название; Кол-во with unit | Цена | Сумма; a discount has name + «Размер скидки» and its product), problem banner, «Удалить» (with confirmation) and «Верно, дальше» (on the last line «Верно»), «Проверено» (tap to unmark). Swipe ≥ 50 px, horizontal-dominant, on the photo or the card; not from a field/button, not with two fingers, not on a zoomed photo; vertical drags scroll. Photo/highlight transitions only after the first move.
- `lineChecks.ts`: line problems (missing price / missing sum / quantity × price ≠ sum, same 0.01 tolerance as the backend), totals check, first problem line.
- Capture screen «Чек распознан» (`ReceiptDetailPage` + new `CaptureLineReview`): lines shown at once in the carousel (no full editor needed), starts at the first problem line; store · date · total on top; bottom bar (new `Page` `footer` slot) with «Магазин, дата и итог ›» (opens the existing full editor, which got «Проверить строки по одной» to go back) and «Сохранить покупку» always visible; «Взять сумму строк» next to a mismatch; change history kept (`ReviewHistory.tsx`, extracted). Save: if the server still reports issues, they are listed and the button becomes «Всё равно сохранить» (as before).
- `IssueReview` (the «Нужно уточнить» cards) removed; its stale header (item 4) is gone — the status is now the live totals line plus per-line banners, recomputed on every edit.
- Saved purchase page: the swipe card stack `LineReview` is replaced by `PurchaseLineReview` (same full-screen modal and entry points: tap a line / header ✓ button; return from a product reopens the same line). Edits are saved to the purchase when leaving the line or on «Верно, дальше» (then it counts as checked); «Удалить» saves the purchase without the line; product link («Изменить товар», «Открыть товар» while unchanged) and product photos/barcodes stay under the line. Approvals still go through `approvalSync` (phone first, batched `POST /api/purchases/line-approvals`).
- Item 3 (draft marks → saved purchase): after «Сохранить покупку» the app loads the saved purchase and, only if it has exactly the draft's lines in order (same count, names, sums), queues the checked ones through the same approval queue (background, not blocking navigation). Otherwise the marks stay visual. The server keeps line order (`ReceiptProcessingService.SaveAsync` orders by position), so this normally maps.
- Help (ru + en): `review-save`, `receipt-lines-photo`, `product-scan` (line media path) rewritten; old swipe-right/left and «Открыть полный редактор» text removed; button names match `i18n.ts`. `topics.ts` unchanged.
- i18n: new `lineCarousel.*`, `receiptReview.*` (ru + en); 36 keys only used by the removed components deleted.
- Storybook: `LineCarousel` (WithProblem, AllChecked, NoBoxFallback, Discount, TwoRowLine, MultiPhoto, NoPhoto, NoReceiptTotal, SmallPhone), `CaptureLineReview` (Recognized, AddsUp), `PurchaseLineReview` (FromHeader, CheckedLine, NoPhoto). Old LineReview / IssueReview stories removed.

## Limitations
- Not tried on a real iPhone/Simulator; swipe tested with mouse pointer events and unit tests.
- Dots: max 8 visible, the window slides with the current line; problem lines far away are reached with the chevrons.
- Leaving the page with an unsaved corrected line open sends it in the background; a failure there cannot be shown (the screen is gone).
- The whole-photo note sits inside the (narrow) photo frame, as in `LinePhoto` elsewhere.

## Review follow-up (2026-10-20)
- Every dismiss of the saved-purchase review commits the corrected line first: `canDismiss` (✕, Escape, swipe-down, hardware back; a failed save keeps it open), plus a save on unmount (browser back / navigation). Test shim: Escape honours `canDismiss`.
- «Взять сумму строк» value formatted as money (locale-aware).
- Missing receipt fields shown compactly above the carousel («Нужно проверить» + list), computed from the current draft (store, date, currency, receipt total; RU/EN keys `receiptReview.missing*`), so a filled-in field disappears at once. The server's recognition-time `receipt.warnings` are not shown in carousel mode (they went stale, e.g. a sum warning next to «Сумма строк сходится»); line sums are covered by the totals line and per-line banners. The full editor still lists `receipt.warnings` as before.
- Dot hit target 24 × 44 px (max 8 dots, fits 320 px).
- Zero recognized lines: short text pointing to «Магазин, дата и итог» (RU/EN, help updated).
- Capture screen in carousel mode uses the compact toolbar title (`Page largeTitle={false}`, as the purchase editor does); the full editor keeps the large title.
- `КОНТЕКСТ_ПРОЕКТА.md` updated.
- Saved-purchase review: a ref flag marks a save/delete in flight; no second save starts meanwhile, and the unmount save is skipped then (no duplicate with a stale version).
- While a correction is being saved, the card fields are read-only (`readOnly` on name and number fields) and late changes are ignored, so nothing typed during the save is erased when it completes (also covers leaving the page mid-save). Chosen over "keep the newer draft": a second save after unmount would carry the stale `expectedUpdatedAt` and hit 409.
- `CapturePage.test.tsx`: the API mock now provides the real `ApiError`; the return-address test waits for the enabled button and the save call.
