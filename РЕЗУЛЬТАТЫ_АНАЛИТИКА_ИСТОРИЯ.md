# Analytics question history (2026-10-08)

Every successful analytics question is saved; repeating it reuses the saved
plan without a model call. Page: «Аналитика» → «Предыдущие вопросы».

## What was built

- **Table `analytics_questions`** (entity `Domain/Analytics/AnalyticsQuestionEntry`):
  question, normalized question (trim, invariant lower case, whitespace
  collapsed), `IsFollowUp`, plan JSON, named-period JSON, answer snapshot JSON,
  conclusion copy, asker (`sub` + email), `CreatedAt`, `AnsweredAt`. Indexes on
  `(NormalizedQuestion, IsFollowUp)` and `AnsweredAt`. JSON is `text` on both
  providers. Migrations: SQLite `20261008150642_AddAnalyticsQuestions`,
  Postgres `20261008150706_AddAnalyticsQuestions` (schema `purchase_memory`).
  SQLite generated via a temporary design-time factory on a scratch DB (deleted).
- **`AnalyticsHistoryService`** (Application) over `IAnalyticsHistoryRepository`
  (Infrastructure, provider-neutral EF):
  - standalone question already in history → `RunAsync` on the saved plan, no
    planner call; entry gets the new words, asker, answer and time;
  - `askModel: true` («Спросить заново») → planner, same entry updated;
  - follow-ups (with `previousPlan`) always go to the planner; saved as
    `IsFollowUp`, deduplicated only when words *and* resulting plan match;
  - a failed history write is logged and the answer still returns (`historyId: null`);
  - only the newest 300 entries are kept.
- **Named periods are recounted.** The planner now returns the period as the
  model named it (`AnalyticsPlanningResult.Period`, e.g. `thisMonth`); it is
  stored, and reuse/refresh resolve it against the new «today». «Keep» (follow-up)
  and missing periods stay as fixed dates.
- **API** (approved-user policy like everything else):
  - `POST /api/analytics/ask` — new optional `askModel`; response = old answer
    fields + `historyId` + `reused`. «Questions disabled» is now decided after the
    reuse check, so a saved question still answers when the model is off.
  - `GET /api/analytics/history?offset=&limit=` (default 20, max 100) →
    `{ items, hasMore }`, newest `answeredAt` first. Items expose
    `askedByEmail` + `askedByMe`, not the asker's id.
  - `GET /api/analytics/history/{id}` → `{ entry, answer }`.
  - `POST /api/analytics/history/{id}/refresh?locale=` → recount, no model;
    shares the run rate limit (429 title «Too many recalculations»).
  - `DELETE /api/analytics/history/{id}` → 204; unknown id → 404 `historyEntryNotFound`.
- **UI**: `AnalyticsHistory.tsx` — list under the answer (question, conclusion
  preview, time, «вы»/email, «Уточнение» badge, trash icon with inline
  «Удалить этот вопрос из истории?» confirm, «Показать ещё» up to 100), and a
  saved-answer bar above the answer with «Обновить» (history entries) and
  «Спросить заново» (not for follow-ups, hidden when questions are off).
  Editing chips clears the saved state. Help: new topic `analytics-history`
  (ru/en) + `HelpLink` in the section header; i18n keys under `analytics.history.*`.

## Decisions

- **Household = the whole deployment.** Data has no household partition in this
  version (КОНТЕКСТ_ПРОЕКТА: shared by all approved users), so the history is
  shared too: every approved member lists, opens, refreshes and deletes any
  entry. There is no "other household" to get a 404; isolation is covered by
  401/403 checks and 404 for unknown ids.
- Server-side reuse only; the client does not short-circuit, so a repeated
  question still consumes one token of the 20/hour question bucket.
- Punctuation is part of the key («молоко?» ≠ «молоко»).

## Limitations / next

- Repeats spend a question-limit token although no model is called.
- MCP has no history tools.
- Snapshot answers keep the language they were computed in until refreshed.
- The list shows up to 100 entries; 300 are stored.

## Review follow-up (2026-10-09)

- Refresh of an entry whose saved plan can't be read (older incompatible
  version) now returns 422 `historyEntryOutdated` instead of a 500
  (`AnalyticsHistoryEntryOutdatedException`, mapped in `AnalyticsEndpoints`).
  GET still returns `answer: null`; asking the same words again plans afresh
  and overwrites the entry. Web shows `analytics.problems.historyOutdated`
  (ru/en); help «Предыдущие вопросы» → trouble explains it.
- The reuse path of `AskAsync` now wraps the history write like `SaveAsync`:
  failure is logged (event 7004) and the answer is returned with
  `historyId: null`.
- `AnalyticsPage`: request token ref (`latestRequest`) — only the latest
  ask/open/refresh/run may replace the answer, problem or saved state; stale
  results are ignored (the history list is still invalidated).
- Delete that hits 404 now clears `activeHistoryId` as well as `saved`.
- After a confirmed delete focus moves to the «Предыдущие вопросы» heading
  (`tabIndex=-1`, focus-visible ring only).
- en `analytics.history.saved` uses “Refresh” quotes.
- Help states explicitly that the history is shared by the household (one
  list; anyone can open/refresh/delete; deletion removes it for everyone).
