## Model-driven тест через Codex

Проведён 15 июля 2026 года. Три независимых сеанса Codex получили только изображение и пользовательскую просьбу сохранить чек; готовый JSON им не передавался.

| Проверка | Короткий чек | Społem | Длинный чек |
|---|---|---|---|
| Клиент | Codex 0.144.2, `gpt-5.6-sol` | Codex 0.144.2, `gpt-5.6-sol` | Codex 0.144.2, `gpt-5.6-sol` |
| Магазин | Распознан | Распознан | Корректно `null`: обрезан |
| Дата | Распознана | Корректно `null`: обрезана | Распознана |
| Итог | 19,70 PLN | 48,04 PLN | 64,33 PLN |
| Читаемых строк | 3 | 7 | 9 |
| Правильно с первого раза | 3 | 6 | 8 |
| Выдуманные строки | 0 | 0 | 0 |
| Исправления | 0 | 1 | 1 ещё требуется |
| `update_purchase_draft` | Не требовался | Успешен после `search` | Не проводился |
| Поиск из нового сеанса | Не проводился | Успешен | Успешен по `OGÓRKI…` |

Итого с первого раза правильно сохранено 17 из 19 названий строк — 89,5%. После разговорного исправления Społem актуальны 18 из 19; в длинном чеке осталось `Masnix` вместо `Masmix`. Модель сохранила повтор `OGÓRKI KWASZONE 870G FRUBEX` двумя строками, а новый сеанс правильно ответил: 2 упаковки × 7,99 PLN, чек 64,33 PLN.

Первый scripted-вызов `update_purchase_draft` был ожидаемо остановлен политикой подтверждений Codex, поскольку tool помечен destructive. Повторный контролируемый прогон с разрешением ровно этого tool завершился успешно. В интерактивном desktop-клиенте пользователь увидит обычный запрос подтверждения.

Подробные источники, эталон и ответы клиента: `test-data/receipts/README.md`.

## Продолженное edge-case тестирование

Проведено 15 июля 2026 года прямыми MCP-вызовами и новыми независимыми Codex-сеансами:

| Сценарий | До исправления | После исправления |
|---|---|---|
| Пустой массив позиций | Безликое `An error occurred` | Модель получает точную причину и не повторяет невалидный вызов |
| Неизвестный `purchaseId` | Безликая ошибка | Возвращается безопасное `was not found` с ID |
| Слишком длинный поиск | Безликая ошибка | Возвращается ограничение 200 символов |
| Повтор того же изображения | Создан второй черновик | Возвращается существующий `purchaseId`, новая запись не создаётся |
| Настоящие одинаковые покупки | Нельзя отличить | Возможен явный повтор с `allowPossibleDuplicate=true` после подтверждения пользователя |
| Ожидаемая ошибка в логе | `[ERR]` и полный stack trace | Одна строка `[WRN]`, неожиданные ошибки по-прежнему логируются полностью |
| Сумма строк 9,00 при итоге 10,00 | Warning существовал только на уровне protocol smoke | Codex самостоятельно показал warning пользователю |

Ответы прогонов сохранены как `07-validation-error-response.md`, `08-duplicate-response.md`, `09-duplicate-protected-response.md` и `10-arithmetic-warning-response.md` в папке `test-data/receipts/results/`.
