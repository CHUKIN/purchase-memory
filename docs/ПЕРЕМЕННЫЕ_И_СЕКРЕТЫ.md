# Переменные и секреты: что где хранить

Короткий ответ на вопрос «куда девать ключи».

1. **В проекте значений нет и не будет.** Ни в коде, ни в `appsettings.json`,
   ни в документах. В проекте лежат только *имена* переменных
   (`docs/secrets.template.env`).
2. **Главное место для секретов — менеджер паролей** (1Password, Bitwarden,
   «Пароли» macOS). Заведите запись «Purchase Memory» и храните там всё из
   колонки «Секрет = да».
3. **Откуда приложение берёт значения:**
   - на вашем Mac — из `~/.zshrc` (как сейчас `OPENAI_API_KEY`) или из файла вне
     проекта, см. ниже;
   - на хостинге — из раздела настроек хостинга «Environment variables /
     Secrets» (вставляете руками из менеджера паролей);
   - во frontend (PWA) не попадает ничего: браузер получает только два
     публичных значения входа, и то с сервера (`/api/auth/config`). Переменных
     сборки frontend у приложения нет.

Двойное подчёркивание `__` в имени — это «вложенность» настроек .NET:
`Storage__S3__Bucket` = `Storage:S3:Bucket` в `appsettings.json`.

## Таблица переменных

«Секрет = да» — значение даёт доступ к данным или деньгам; его нельзя
показывать, пересылать в чатах и вставлять в скриншоты. «Нет» — значение
публичное или просто настройка, но всё равно задаётся через окружение.

### Вход (Supabase Auth)

| Переменная | Что это | Где взять | Секрет | Куда вписать |
|---|---|---|---|---|
| `Auth__SupabaseUrl` | Адрес проекта Supabase | **Project Settings → Data API** (или главная проекта): Project URL `https://<ref>.supabase.co` | нет | `~/.zshrc`; хостинг |
| `Auth__SupabasePublishableKey` | Публичный ключ для входа | **Project Settings → API Keys → Publishable key** (`sb_publishable_…`) | нет | `~/.zshrc`; хостинг |
| `Auth__Providers__0`, `__1`, … | Кнопки входа (`email`, `google`, …) | ваш выбор | нет | по желанию |
| `Auth__DevelopmentBypass` | Вход без Supabase на своём Mac | — | нет | **только** локально, **никогда** на хостинге |

Ключ `sb_secret_…` / `service_role` приложению **не нужен**. Не вписывайте его никуда.

### База данных

| Переменная | Что это | Где взять | Секрет | Куда вписать |
|---|---|---|---|---|
| `Database__Provider` | `Sqlite` (по умолчанию, файл `data/purchases.db`) или `Postgres` | ваш выбор | нет | хостинг: `Postgres` |
| `ConnectionStrings__Postgres` | Строка подключения к Postgres Supabase | кнопка **Connect** вверху проекта → **Session pooler**, см. `docs/SUPABASE_БАЗА_И_ФОТО.md` | **да** (в ней пароль БД) | хостинг; локально — только если хотите проверить с Supabase |

Пароль базы задаётся при создании проекта и меняется в **Project Settings →
Database → Reset database password**.

### Фото чеков

| Переменная | Что это | Где взять | Секрет | Куда вписать |
|---|---|---|---|---|
| `Storage__Provider` | `Local` (по умолчанию, папка `data/receipts`) или `S3` | ваш выбор | нет | хостинг: `S3` |
| `Storage__S3__ServiceUrl` | Адрес S3 у Supabase Storage | **Project Settings → Storage → S3 Connection → Endpoint** (`https://<ref>.storage.supabase.co/storage/v1/s3`) | нет | хостинг |
| `Storage__S3__Region` | Регион проекта | там же, **Region** (например `eu-central-1`) | нет | хостинг |
| `Storage__S3__Bucket` | Имя бакета | вы создаёте `receipts` (по умолчанию так и называется) | нет | хостинг |
| `Storage__S3__KeyPrefix` | Необязательная «папка» внутри бакета | ваш выбор, можно пусто | нет | по желанию |
| `Storage__S3__AccessKeyId` | Имя ключа доступа S3 | **Storage → S3 access keys → New access key** | **да** (считаем секретом) | хостинг |
| `Storage__S3__SecretAccessKey` | Секрет ключа S3 | показывается **один раз** при создании ключа | **да** | хостинг |

S3-ключи Supabase дают полный доступ ко всем бакетам проекта в обход правил
доступа. Храните их как пароль. Если ключ утёк — удалите его в том же разделе и
создайте новый.

### Распознавание чеков

| Переменная | Что это | Где взять | Секрет | Куда вписать |
|---|---|---|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI (основной путь распознавания, платно) | platform.openai.com → API keys | **да** | `~/.zshrc`; хостинг |
| `OLLAMA_API_KEY` | Ключ Ollama cloud (запасной путь) | ollama.com → Settings → Keys | **да** | по желанию |
| `ReceiptRecognition__*` | Модели, таймауты, пайплайн | уже заданы в `appsettings.json` | нет | менять не нужно |
| `Categorization__*` | AI-подсказки категорий (`Enabled`, `Model` = `gpt-6-luna`, `BatchSize`…), тот же `OPENAI_API_KEY` | уже заданы в `appsettings.json` | нет | `Categorization__Enabled=false` выключает платные подсказки |
| `Analytics__*` | вопросы в «Аналитике» (`Enabled`, `Model` = `gpt-6-luna`, `MaximumOutputTokens` = 2000, `TimeZone` = `Europe/Warsaw`), тот же `OPENAI_API_KEY` | уже заданы в `appsettings.json` | нет | `Analytics__Enabled=false` выключает платные вопросы; фильтры готового ответа и MCP `run_analytics_plan` работают без модели |
| `RateLimiting__AnalyticsQuestions__*` | лимит вопросов на пользователя (`TokenLimit` = 20, пополнение 1 раз в 180 с ≈ 20 в час) | уже заданы | нет | — |
| `ReceiptImages__AnalysisSource` | Какую копию фото получает распознавание: `Original` (по умолчанию) или `Viewing` (сжатая) | см. `РЕЗУЛЬТАТЫ_POSTGRES_И_ХРАНИЛИЩЕ.md` | нет | не менять без замера |
| `ReceiptImages__DisplayCopy__Enabled`, `__MaximumLongSidePixels`, `__JpegQuality` | Сжатая копия фото (по умолчанию: вкл., 2400 px, 82) | — | нет | менять не нужно |

### Прочее

| Переменная | Что это | Секрет |
|---|---|---|
| `ASPNETCORE_ENVIRONMENT` | `Production` на хостинге, `Development` локально | нет |
| `Paths__DataDirectory`, `Paths__LogDirectory` | Папки данных и логов | нет |
| `RateLimiting__ReceiptUploads__*` | Лимит загрузок чеков | нет |
| `PORT` | Порт, который слушает контейнер (`0.0.0.0:$PORT`; в образе по умолчанию 5099, Render ставит 10000). В Development не используется | нет |
| `ReverseProxy__TrustForwardedHeaders` | `true` только за прокси хостинга (Render): брать адрес клиента и HTTPS-схему из последней записи `X-Forwarded-*`. Локально не включать; вместе с `Auth__DevelopmentBypass` запрещено. См. `docs/ДЕПЛОЙ_RENDER.md` | нет |

## Локальный файл с секретами (если не хотите держать всё в `~/.zshrc`)

1. Скопируйте шаблон **вне проекта**:
   ```bash
   mkdir -p ~/.config/purchase-memory
   cp docs/secrets.template.env ~/.config/purchase-memory/secrets.env
   chmod 600 ~/.config/purchase-memory/secrets.env
   ```
2. Заполните копию (значения — из менеджера паролей). Каждое значение — в
   двойных кавычках: в строке подключения есть `;`, и без кавычек zsh её обрежет.
3. Подключите её в `~/.zshrc` одной строкой:
   ```bash
   set -a; [ -f ~/.config/purchase-memory/secrets.env ] && . ~/.config/purchase-memory/secrets.env; set +a
   ```
   Пустые строки из шаблона тоже станут переменными с пустым значением —
   удалите из копии то, что не заполнили.

Не кладите заполненный файл в папку проекта, в iCloud Drive/Dropbox с общим
доступом и не прикладывайте его к сообщениям. В `.gitignore` на будущее уже
стоит правило `*.env` (кроме шаблона).

## Что делать, если ключ попал куда не надо

(в чат, в скриншот, в файл проекта, в лог)

1. Сразу отзовите его там, где он выдан (OpenAI → API keys; Supabase →
   Storage → S3 access keys; пароль БД → Reset database password).
2. Создайте новый, положите в менеджер паролей и обновите переменную на хостинге
   и в `~/.zshrc`.
3. Старое значение больше нигде не используйте.
