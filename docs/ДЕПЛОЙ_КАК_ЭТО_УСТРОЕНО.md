# Как устроен деплой: Render, Supabase, GitHub, OpenAI

Объяснение для владельца, без DevOps-жаргона. Что настроено, зачем, где оно
живёт и что будет, если ключ утечёт или настройку выключить.

Технические инструкции «как сделать» лежат отдельно:
`docs/ДЕПЛОЙ_RENDER.md`, `docs/SUPABASE_AUTH_SETUP.md`,
`docs/SUPABASE_БАЗА_И_ФОТО.md`, `docs/ПЕРЕМЕННЫЕ_И_СЕКРЕТЫ.md`.

## Общая картина

```
 Телефон / браузер
        │  https://purchase-memory.onrender.com
        ▼
 ┌──────────────── Render ────────────────┐
 │  контейнер с приложением (.NET + сайт)  │
 └───┬───────────────┬───────────────┬────┘
     │ вход (токен)  │ база и фото   │ распознавание
     ▼               ▼               ▼
 Supabase Auth   Supabase Postgres  OpenAI
                 + Storage (S3)
        ▲
 GitHub (ghcr.io) — склад, откуда Render берёт готовый образ приложения
```

Путь одного чека:

1. Вы входите. Supabase выдаёт телефону **токен**, пропуск на час.
2. Телефон отправляет фото на Render вместе с токеном.
3. Приложение проверяет пропуск и кладёт фото в хранилище Supabase. Рядом
   ложится сжатая копия для экрана.
4. Приложение отправляет фото в OpenAI и получает список позиций.
5. Результат сохраняется в базу Supabase.

Ни Render, ни GitHub ваших покупок не хранят. Данные живут только в Supabase.

## Render — где работает приложение

### Сервис `purchase-memory`
- **Что это.** Арендованный маленький компьютер (512 МБ памяти, 0,1
  процессора), на котором запущено приложение. Бесплатный тариф, регион
  Франкфурт.
- **Зачем.** Чтобы приложение было доступно с телефона из любого места, а не
  только когда включён Mac.
- **Где.** dashboard.render.com → `purchase-memory`. Там же **Logs**
  (журнал), **Events** (запуски) и **Environment** (настройки).
- **Особенность бесплатного тарифа.** После ~15 минут без запросов сервис
  засыпает. Первое открытие после сна ждёт 30–60 секунд, дальше всё быстро.
  Данные при этом не теряются: они в Supabase, а не на Render.
- **Диск временный.** Всё, что приложение запишет на диск Render, пропадает
  при перезапуске. Поэтому база и фото вынесены в Supabase.

### Деплой из образа
- **Что это.** Образ (Docker image) — запечатанная коробка с приложением,
  всеми библиотеками и собранным сайтом. Render не собирает приложение сам, а
  берёт готовую коробку из GitHub (`ghcr.io/chukin/purchase-memory`).
- **Зачем.** Сборка на бесплатном Render медленная и упирается в память.
  Собрать на Mac и привезти готовое надёжнее.
- **Как обновлять.** На Mac `scripts/publish-image.sh` собирает и выкладывает
  новый образ. Потом в Render **Manual Deploy → Deploy latest reference**.
  Автодеплой выключен специально: новая версия попадает к вам, только когда вы
  этого хотите.

### Health check `/health`
- **Что это.** Адрес, который Render опрашивает каждые несколько секунд:
  «жив?». Отвечает «healthy» и больше ничего не раскрывает.
- **Зачем.** Если приложение зависло или не стартовало, Render это видит и не
  переключает трафик на сломанную версию. Старая версия продолжает работать.
- **Если выключить.** Render будет считать живым любой запущенный контейнер,
  даже неработающий.

### Переменные окружения (Environment)
Это настройки, которые Render передаёт приложению при запуске. Их два вида.

**Обычные** (не секрет, вписаны агентом):

| Переменная | Что значит |
|---|---|
| `ASPNETCORE_ENVIRONMENT=Production` | Боевой режим: строгие проверки, вход без пароля запрещён |
| `PORT=10000` | На каком порту приложение ждёт Render |
| `ReverseProxy__TrustForwardedHeaders=true` | Доверять пометкам прокси Render: какой у посетителя адрес и что соединение HTTPS |
| `Database__Provider=Postgres` | База — Postgres в Supabase (а не файл SQLite, как на Mac) |
| `Storage__Provider=S3` + `Storage__S3__*` | Фото — в хранилище Supabase: адрес, регион, имя бакета `receipts` |
| `Auth__SupabaseUrl`, `Auth__SupabasePublishableKey` | Адрес проекта Supabase и его публичный ключ — для входа |

**Секретные** (вписали вы, агент их не видел):

| Переменная | Что это | Если утечёт |
|---|---|---|
| `OPENAI_API_KEY` | Ключ оплаты распознавания | Кто-то тратит ваши деньги на OpenAI. Лимит бюджета в OpenAI ограничивает ущерб. Отозвать ключ в OpenAI, создать новый, вписать в Render |
| `ConnectionStrings__Postgres` | Адрес базы + пароль | Полный доступ к базе: прочитать и удалить все покупки. Сменить пароль БД в Supabase (**Database → Settings → Reset password**), обновить строку в Render |
| `Storage__S3__AccessKeyId` / `SecretAccessKey` | Пара ключей к хранилищу фото | Доступ ко всем фото чеков. Удалить ключ в Supabase (**Storage → S3 Connection**), создать новый, вписать в Render |

Чего там **нет и быть не должно**: `Auth__DevelopmentBypass` (вход без пароля
для разработки на Mac) и `ReceiptRecognition__BaseAddress` (адрес локального
Ollama). Если первый появится, приложение в боевом режиме просто не
запустится — это защита.

### Registry Credential `github`
- **Что это.** Токен GitHub, сохранённый в Render (**Settings → Registry
  Credentials**), с одним правом `read:packages` — «только скачивать образы».
- **Зачем.** Образ закрытый, без пропуска Render его не скачает.
- **Если утечёт.** Посторонний сможет скачать образ, то есть код приложения.
  Данных и ключей в образе нет: они только в переменных Render. Отозвать
  токен на github.com → **Settings → Developer settings → Tokens**.

### API-ключ Render (`RENDER_API_KEY` в `~/.zshrc`)
- **Что это.** Ключ, через который агент создавал сервис и смотрит журналы.
- **Если утечёт.** Управление всеми вашими сервисами на Render, включая
  `sabianbot` и `businka_tg`. Отозвать в Render → **Account Settings → API
  Keys**.

## Supabase — данные, фото и вход

Проект `nycrbyergcbadxxlyyoj`, регион Лондон (`eu-west-2`), бесплатный тариф.

### Auth — вход
- **Что это.** Готовая система входа: письмо со ссылкой или кодом, кнопка
  Google. Supabase хранит список людей (**Authentication → Users**) и выдаёт
  им пропуск — **токен (JWT)**.
- **Зачем.** Чтобы не писать и не хранить пароли самим.
- **Токен** — подписанная записка «это такой-то человек, действует до …».
  Живёт час, потом телефон тихо получает новый.

### Ключи подписи (JWT Keys)
- **Что это.** Supabase подписывает токены закрытым ключом, а приложение
  проверяет подпись открытым ключом, который берёт с сайта Supabase.
  Подделать подпись без закрытого ключа нельзя.
- **Почему не «Legacy JWT secret».** Старая схема — один общий пароль,
  которым и подписывают, и проверяют. Приложение такие токены не принимает
  вообще. Это проверено попытками подделки при review.
- **Если что-то случилось.** Ротация в **Project Settings → JWT Keys**: новый
  ключ, старые токены перестают действовать.

### Таблица `app_users`, триггер и хук — «кого пускать»
Supabase пустит любого, у кого есть почта. Поэтому поверх стоит свой
привратник:

1. **Триггер.** Как только новый человек входит впервые, в таблицу
   `public.app_users` автоматически добавляется строка со статусом
   `pending` («ждёт»).
2. **Вы решаете.** В **Table Editor → app_users** меняете статус на
   `approved` или `blocked`.
3. **Хук `custom_access_token_hook`.** Каждый раз, когда Supabase выдаёт
   токен, хук дописывает в него статус человека (`app_access`).
4. **Приложение** пускает только тех, у кого в токене `approved`.

- **Если хук выключить.** В токенах не будет статуса, и приложение не пустит
  никого, даже вас. Так задумано: при поломке оно закрывается, а не
  открывается.
- **Почему статус меняется не мгновенно.** Он записан в токен, а токен живёт
  час. Кнопка «Проверить снова» берёт новый токен сразу. Блокировка
  срабатывает не позже чем через час.
- **Защита таблицы.** На ней включена RLS (row level security, «защита
  строк»): через публичный ключ её не прочитать, читать может только сервер
  входа.

### Publishable key vs secret key
- **Publishable key** (`sb_publishable_…`) — публичный, «адрес двери». Он
  виден в браузере любому, это нормально. Сам по себе он ничего не открывает.
- **Secret key / service_role** — ключ «от всего». Приложению он **не
  нужен** и нигде не вписан. Никому не давать.

### Postgres через Session pooler — база
- **Что это.** Сама база данных. Приложение подключается к ней через
  «пулер» (`aws-0-eu-west-2.pooler.supabase.com`) — посредника, который
  держит соединения. Прямой адрес базы бесплатный Render не достанет (там
  только IPv6), а пулер доступен.
- **Где данные.** Все таблицы приложения — в отдельной схеме
  `purchase_memory` (**Table Editor → schema: purchase_memory**). Приложение
  само создаёт и обновляет их при запуске (миграции).
- **Предупреждение «RLS disabled» на таблицах `purchase_memory`.** Для нас не
  опасно: у публичных ролей Supabase нет к этой схеме доступа вовсе.
  Приложение ходит в базу как её владелец. Это проверено запросом.
- **Формат строки.** Приложение понимает только вид
  `Host=…;Port=5432;Database=postgres;Username=postgres.<проект>;Password=…;SSL Mode=Require`,
  а не ссылку `postgresql://…`. Из-за этого падал второй запуск.

### Storage — фото чеков
- **Бакет `receipts`** — папка для фото, **закрытая**: по прямой ссылке фото
  не открыть. Его отдаёт только приложение и только вошедшему человеку.
- **S3-ключи.** Приложение говорит с хранилищем на «языке S3» (стандарт
  Amazon), поэтому нужна своя пара ключей. Они дают доступ только к
  хранилищу, не к базе.
- На каждый чек хранится оригинал и сжатая копия для экрана.

### Data API — выключен
- **Что это.** Встроенная возможность Supabase отдавать таблицы прямо в
  браузер по публичному ключу.
- **Почему выключен.** Приложению не нужен. Работает — значит, это лишняя
  дверь. Проверено: публичный ключ таблиц не видит.

### Правки по проверке безопасности (Advisors)
Короткий SQL закрыл предупреждения Supabase: служебные функции нельзя
вызвать снаружи, хук читает таблицу только по полному имени (защита от
подмены).

### Важно про бесплатный Supabase
- **Засыпание.** Если в проект ~7 дней никто не ходит, Supabase ставит его на
  паузу. Приложение перестанет открываться, пока вы не нажмёте **Restore** в
  панели. Данные не теряются.
- **Резервные копии.** На бесплатном тарифе их нельзя скачать, и нет
  восстановления на любой момент. Когда данных станет много, стоит сделать
  свою регулярную выгрузку.

## GitHub — склад образов (и скоро код)

### GHCR (`ghcr.io/chukin/purchase-memory`)
- **Что это.** Хранилище образов на GitHub, раздел **Packages** в профиле.
  Пакет **закрытый**: без входа скачать нельзя (проверено, ответ 401).
- **Теги.** У каждой выкладки есть метка времени (например
  `20261006-1240`) и метка `latest` — «последний». Render берёт `latest`.
  По метке времени можно откатиться на старую версию.

### Права `gh` на Mac
- `gh` (программа GitHub в терминале) вошла как `CHUKIN` с правом
  `write:packages` — выкладывать образы. Скрипт берёт токен у `gh` и не
  печатает его. После выкладки выходит из реестра.
- Токен для Render — отдельный, только `read:packages`. Разделение нужно,
  чтобы утечка с одной стороны не давала прав другой.

## OpenAI — распознавание

- **Что.** Модель `gpt-6-sol` читает фото и возвращает магазин, дату, сумму и
  позиции. Один чек — около цента или двух, примерно 20–30 секунд.
- **Ключ** — только в Render (`OPENAI_API_KEY`) и в `~/.zshrc` на Mac.
- **Лимит бюджета** в OpenAI (**Settings → Limits**) — главная защита от
  неожиданного счёта.
- Локальные модели (Ollama, Apple) в облаке не работают — только на Mac.

## Что делать, если…

| Ситуация | Что делать |
|---|---|
| Приложение долго открывается | Нормально после сна Render, подождать до минуты |
| Не открывается совсем | Render → Logs; Supabase → не на паузе ли проект |
| Новый человек не может войти | Supabase → Table Editor → `app_users` → поставить `approved` |
| Кажется, утёк ключ | Отозвать в сервисе (таблица выше), создать новый, вписать в Render → Environment → Save (Render перезапустит сервис) |
| Нужна новая версия приложения | `scripts/publish-image.sh`, затем Render → Manual Deploy |
| Новая версия сломалась | Render → Events → откатиться на прошлый деплой (Rollback) |
