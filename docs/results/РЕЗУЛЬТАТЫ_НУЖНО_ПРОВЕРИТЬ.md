# Результаты этапа «Нужно проверить» (очередь проверки)

Дата: 26.09.2026.

## Что сделано

Вместо заглушки на странице `/needs-attention` теперь настоящая очередь:
список того, что стоит поправить или подтвердить, чтобы данные были точными.
Очередь считается на лету из уже сохранённых данных — без вызовов AI и без
новых таблиц (миграций нет).

Что попадает в очередь (группы на странице):

| Группа | Когда | Что можно сделать |
|---|---|---|
| Чек не распознан | распознавание завершилось ошибкой | открыть чек и повторить |
| Чек ждёт сохранения | чек распознан, покупка не сохранена | открыть чек и сохранить |
| Сумма не сходится | сумма строк со скидками отличается от итога чека больше чем на 0,01 | открыть чек |
| Нет цены | в сохранённой покупке есть строки без цены | открыть чек |
| Товар не сопоставлен | строка похожа на товар из каталога, но связать автоматически не хватило уверенности | открыть похожий товар или чек |
| Категория не подтверждена | категорию предложил AI | **подтвердить в один клик** или изменить на странице товара |
| Без категории | у товара нет категории и никто не решил «без категории» | выбрать категорию на странице товара |

Правила «сумма не сходится» и «нет цены» — те же, что при проверке чека до
сохранения (`PurchaseDraftIssueDetector`), поэтому две проверки не расходятся.

Кнопка «Подтвердить» использует существующий `PUT
/api/products/{id}/classification`. В меню у пункта «Нужно проверить»
появилось число пунктов (обновляется после действий, после завершения
распознавания чека и раз в минуту).

## Для разработчика

- `GET /api/review-queue?limitPerKind=20` (1–100) — группы с общим числом и
  первыми N пунктами; `GET /api/review-queue/count` — только числа для значка.
- Доступ как у остальных данных: только одобренный пользователь. Данные в этой
  версии общие для всех одобренных пользователей, поэтому очередь тоже общая.
- MCP-инструмент `list_review_queue` (только чтение).
- Код: `src/PurchaseMemory.Application/ReviewQueue/`,
  `src/PurchaseMemory.Infrastructure/ReviewQueue/`,
  `src/PurchaseMemory.Api/Endpoints/ReviewQueueEndpoints.cs`,
  `src/PurchaseMemory.Api/Mcp/ReviewQueueTools.cs`,
  `src/PurchaseMemory.Web/src/features/review-queue/`.

## Ограничения

- Отклонить («скрыть») пункт нельзя — для этого нужна отдельная таблица;
  решили не добавлять миграцию на этом этапе.
- Сохранённую покупку в интерфейсе пока нельзя редактировать, поэтому пункты
  «Сумма не сходится» и «Нет цены» у сохранённых покупок ведут на просмотр
  чека, но исправить там нельзя. Исправление возможно через MCP
  (`update_purchase_draft`). Это главный кандидат на следующий шаг.
- «Нет цены» срабатывает и когда у товара есть сумма строки, но нет цены за
  единицу — так же, как при проверке чека.
- Для «Товар не сопоставлен» нет экрана, где связать строку с товаром;
  ссылка ведёт на похожий товар для сверки.
- Проверяются последние 5000 покупок (для семьи — всё).
- Числа на значке меню на телефоне не видно: пункта «Нужно проверить» нет в
  нижней навигации (как и раньше), вход — с главной.

## Следующий кандидатный шаг

Редактирование сохранённой покупки (строки, цены, итог) из очереди и экран
сопоставления строки с товаром; при необходимости — «скрыть пункт».

Мелочи на потом:

  нужен запасной формат.
- Бейдж раз в минуту делает полный пересчёт — при росте данных кешировать.
- У покупки без чека ссылка ведёт на общий список, а не на саму покупку.
- MCP-инструмент молча ограничивает лимит, а HTTP отвечает 400.
- Нет редактирования сохранённой покупки в интерфейсе — главный следующий шаг.

## Для подсказок

- «Нужно проверить» — очередь того, что стоит поправить: неудачное или
  несохранённое распознавание, сумма не сходится, нет цены, строка не связана
  с товаром, категория предложена ИИ или не выбрана.
- Предложенную категорию можно подтвердить одной кнопкой; остальное — по
  ссылке на чек или товар. Счётчик в меню показывает, сколько пунктов осталось.
