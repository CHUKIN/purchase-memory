# Stage 1.6 — «Ревью» hub: results

Level: Обычный (screens + endpoint extension, no migrations). Branch `feature/home-cards` (on top of b1eb749), uncommitted.

## Done

- **Home**: the «Нужно проверить» row is replaced by a «Ревью» card under the capture tiles (`features/home/HomeReviewCard.tsx`). It uses mock A styling: white card with a 1px #e1e1e6 border and radius 16. When something is waiting it turns warm (#fdf3e6 / #f1d9b8) with ⚠ and the count (99+ cap, same as the tab badge). With nothing waiting it shows «Всё проверено» and no count. While the count is unknown it is a plain card. The tab badge and the card read one hook, `useReviewCount`: the server summary total plus the barcodes remembered on this device.
- **Endpoint**: `GET /api/review-queue` and `/count` now serve the hub:
  - New kinds: `unapprovedLines` (one item per purchase saved in the last 30 days — same window as ratings, so older history does not flood the hub — with lines not marked «Верно», with `affectedLineCount`, `lineCount` and `itemPosition` = first unchecked line) and `unratedPurchase` (the caller's own recent unrated lines, with `purchaseItemId`, `merchantName` and `price`; same source as «Оценить недавнее», 30 days, max 50).
  - New `summary` block `{ totalCount, sections: [{ section, count }] }` for receipts / purchases / products / categories / ratings. It is never filtered, and `totalCount` = sum of sections.
  - `/count` also returns `summary`.
  - Ratings are per user (from the token). The rest is the household's shared data, as in every other endpoint.
  - EF only, no provider-specific SQL. The MCP tool still uses `GetAsync` (data kinds only, no summary).
- **Hub** (`/needs-attention`, route kept): sections appear in order of importance, only when non-empty, each with a count. Order: Чеки → Покупки → Товары → Категории → Штрихкоды → Оценить покупки.
  - Each section shows 3 items, then «Показать все» (kept in the URL as `?open=`).
  - Purchases: «Проверить строки» opens the purchase straight into the line carousel on the first unchecked line. This happens once per history entry (`openLineReview.ts`).
  - Products: «Да, это он» (confirm alert, never bulk) / «Это другой товар».
  - Categories: «Подтвердить» / «Изменить» / «Выбрать категорию», plus bulk «Принять все предложенные (N)».
    - The bulk action re-reads up to 100 suggested categories with the screen's filters. With more than 100, the button says «Принять первые предложенные (100)».
    - It hides the items at once and shows a toast with «Вернуть». The categories are confirmed when the toast is gone, or as soon as the page is hidden or closed (`pagehide` / `visibilitychange`). The server cannot un-confirm a category, so a late «Вернуть» says they are already accepted.
  - Barcodes: codes saved with «Запомнить на потом» (on this device, IndexedDB) can be linked to a product through the catalog search modal, or forgotten.
  - Ratings: rate in place.
  - The category/tag filters are kept.
- **Fast mode «Проверять по одной»** (`?cards=<section>`, its own history step) for Товары, Категории and Оценить покупки (`ReviewCards.tsx`).
  - Progress «N из M» and a progress bar. Buttons: «Верно, дальше», «Пропустить» and previous.
  - Swipes reuse the line carousel's gesture (now in `line-review/useSwipe.ts`): left = next card, right = previous.
  - After the last card it goes back to the hub. «Открыть товар» remembers the card, so «Назад» lands on the same card.
- **Return-to-place**: every link carries the return state, and sheets/modals are one back step (existing mechanisms). The toast gained a `run` action and `onDismiss`.
- **Help**: the «Ревью» topic replaces the «Нужно проверить» wording (ru + en). Button names were checked against `i18n.ts`. Keys: `common.review` = «Ревью» / "Review", new `reviewQueue.sections/cards/barcodes/...`. The unused `reviewQueue.openPurchases` was removed.
- **Stories**:
  - `HomeReviewCard.stories.tsx` (pending / en / 99+ / all checked / unknown).
  - Hub, «Показать все», all-checked and three card-mode stories in `ReviewQueuePage.stories.tsx`.
  - `Screens` stubs now include the new kinds and summary, plus a `ReviewCardsMobile` screen.

## Skipped / decisions

- Names «предложено» (Stage 1.4) are not done. The section list (`reviewSections.ts`) has a slot noted for it.
- Fast mode is not offered for Чеки, because each receipt needs its full editor. It is also not offered for Покупки, because a purchase's lines already are a card carousel, which «Проверить строки» opens. Barcodes need a product search, so they are not offered either.
- Swipe direction follows the existing line review (page turning), not "right = accept". Accepting is always an explicit button, so a stray swipe never writes anything.
- Barcodes are device-local (no backend yet), so they are counted on the client and added to the server total. With a category/tag filter they are hidden.

## Limitations

- Card mode loads up to 100 items per kind. «N из M» counts the loaded cards, not a larger section total.
- Purchases saved more than 30 days ago are not in «Покупки» even if their lines were never checked. Their lines can still be checked in the purchase itself.
