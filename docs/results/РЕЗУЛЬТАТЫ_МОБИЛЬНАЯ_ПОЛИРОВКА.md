## Problems found (before)

1. Purchase edit form scrolled sideways: 584 px wide at 375 px, 600 px at 430 px. The
   discount editor and header fields used `1fr`/`auto` grid tracks that grow to the longest word.
2. Purchase detail: long line names pushed the amount to its own row under the name; the
   «Нет цены» badge and price drifted left; «Оценить» took a full row per line.
3. Product detail: price table dates broke into three lines («9 авг. / 2026 / г.»); the
   receipt-names list gave the store key a fixed wide column and squeezed the printed name to
   one word per line.
4. Rating buttons (Не нравится / Средне / Нравится) wrapped 2 + 1 on phones (Home, product page).
5. Category manager: subcategory rename/delete icons wrapped under the name; icons were
   Mantine buttons with hidden text, no tooltip.
6. Product «Изменить» / «Изменить теги» were full-width secondary text buttons.
7. Receipt progress card: the status badge squeezed the title into a narrow column
   («Нужна / повторная / попытка»).
8. Product and purchase cards cut long names to one line with an ellipsis.
9. Filter/search/select/textarea fields at 14–15 px: iOS zooms the page on focus.
10. Small things: the «×» glyph as delete, «＋» glyph in button names, help/back links
    under 44 px tall, prices without tabular figures.

## Fixes

Design system / global:
- New `IconButton` (`design-system/components/IconButton`): `label` = `aria-label` + tooltip
  (Mantine Tooltip on hover/keyboard focus, hidden when the text is visible), optional shorter
  `text`, `intent` (primary/secondary/quiet/danger), `iconOnly="always" | "mobile"` (text from
  40em up), `loading`, 44 × 44 px target, 3 px focus ring. Stories with Controls + RU/EN
  (`Components/IconButton`), unit test.
- `styles.css`: tokens `--pm-touch-target`, `--pm-safe-left/right/bottom`; `body { overflow-wrap:
  break-word }`; `text-size-adjust: 100%`.
- AppShell: safe-area insets left/right for header, content and bottom nav; `overflow-x: clip`
  on the content as a last guard; bottom-nav labels 0.7rem.

Screens:
- Purchase detail/edit: `minmax(0, 1fr)` grids, line = name | amount (amount pinned top-right,
  badge above price), compact «Оценить» on the right, number inputs aligned when labels wrap,
  Save/Cancel thumb-sized, back link with arrow; «×» → trash `IconButton`; «＋» glyph → Plus icon.
- Discount line, receipt progress, price table, aliases, impressions, rating control (3 equal
  tiles on phones), feed/catalog cards (2-line clamp + `title`), category/tag managers
  (`IconButton`, actions stay on the name's line), product classification/tags (pencil
  `IconButton` in the section header; text visible from 40em).
- 16 px font for inputs on touch devices (feed, catalog, classification filters, impressions).

Icons chosen only where the meaning is obvious: edit (pencil), delete/remove (bin). Primary
actions («Исправить», «Подтвердить», «Сохранить…», «Оценить», «Сфотографировать чек») stay text.

Accessible names are unchanged except «＋ Добавить строку» → «Добавить строку» (one test
updated). `PurchaseDetailPage.test.tsx` mock now also defines `createImpression`/`deleteImpression`
(a latent race made one test flaky once impressions rendered after save).

Help (`helpText.ts`, ru + en): purchase edit (bin on a line), categories (pencil next to the
block title, manager pencil/bin), tags (pencil, manager pencil/bin), impressions (bin).
Quoted labels still match `i18n.ts` («Изменить», «Изменить теги», «Удалить», “Change”, “Edit
tags”, “Delete”, “Correct”).
