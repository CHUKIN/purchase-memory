# Stage 1.5 — Name from the product photo: results

Level: Полный (paid vision AI). No migration. No paid call was made in this stage; all tests use fakes.

## Done

- **API** `POST /api/products/{id}/name-from-photo` (multipart, one file field `photo`).
  - Server checks: exactly one file; at most 1.5 MB (413 `photoTooLarge`); JPEG/PNG/WebP by magic bytes, not by the declared type (415 `photoNotAnImage`); empty/missing/wrong field or not multipart → 400 `photoMissing`. Request size cap 2 MB.
  - Approved-user fallback policy like every product endpoint; own per-user bucket `name-from-photo` (`RateLimiting:NameFromPhoto`, default 20 burst, then 1 per 3 min; 429 title «Too many photo names»).
  - 503 `nameFromPhotoUnavailable` when the namer is off / has no key / the provider fails (details only in the log).
  - The photo is held in memory for the call only: not stored, not logged (no bytes, no base64; logs carry byte count, model, timing, tokens, cost).
- **Rule per language** (`ProductPhotoNamingService`, reuses the 1.4 conditional write `ApplyNameSuggestionAsync(replaceSuggested: true)`):
  - source null or Suggested → replaced, stays `Suggested`; response gives `previousName` / `previousSource` for «Вернуть».
  - Confirmed → untouched, returned as `proposed`.
  - same name → `unchanged`; model unsure (null) → `notRead`.
  - Audit entry per replaced language: actor = the user who sent the photo, source `suggestion`, `old (suggested)` → `new (suggested)`.
- **Undo** `POST /api/products/{id}/names/undo-photo` `{ language, photoName, previousName }`: only if the name is still the photo's suggested one (else 409); restores the previous suggestion, or no name (receipt text) — not a confirmed name. Human audit entry. New domain method `Product.RestoreSuggestedName`.
- **Namer** `IProductPhotoNamer` (Application) → `AnthropicProductPhotoNamer` (Infrastructure), same Messages transport / key (`ANTHROPIC_API_KEY`) as receipts and tags. Config `ProductPhotoNaming:{Enabled, Model=claude-haiku-5-5, Effort=Low, RequestTimeoutSeconds=45, MaximumRetries=1, MaximumOutputTokens=4000}`, validated at startup.
  - Structured output: `brand, product, variant, size, namePl, nameRu` (all nullable). Prompt follows the 1.4 naming prompt (format «Kefir naturalny Activia 280 g» / «Кефир натуральный Activia, 280 г», null rather than a guess). Receipt text + known brand passed as context only («the package wins»), one quoted line.
  - Returns token usage and estimated cost; completion logged as event 3433, failures 3434, service outcome 3432.
- **Frontend**
  - `useNameFromPhoto` hook: shrinks to a ≤ ~200 KB JPEG (1024 px, `photoForNaming`), calls the endpoint, refreshes products / purchases / review queue.
  - Replaced → toast «Название обновлено по фото: PL · RU» with «Вернуть» (undo per language; 409 → quiet «Не получилось вернуть…»).
  - Proposed → IonAlert «Предложить название» — «По фото: … Заменить?»; «Заменить» saves via `PUT …/name` (confirmed, the person chose it).
  - Nothing read / same name / any error → one quiet toast; automatic run is skipped while offline.
  - Runs automatically after a photo is added on the product card (both variants) and from the purchase line sheet; button «Название по фото» under the photos on the product card when a device photo exists (reads the main photo).
  - i18n ru + en (`products.names.fromPhoto*`).
- **Help**: `product-names` (step, «see», two «trouble» items) and `product-scan` (pointer) updated in ru + en; button names match i18n.
- **Measurement tool** `tools/PurchaseMemory.PhotoNameBenchmark` (not run).

## Measurement tool

```
zsh -ic './scripts/dotnet.sh run --project tools/PurchaseMemory.PhotoNameBenchmark -- <photos-folder> <out.csv> --budget-usd 0.05 [--model claude-haiku-5-5] [--limit 20]'
```

- Reads `.jpg/.jpeg/.png/.webp` (HEIC usually fails to decode → row with error, no call), shrinks like the app (1024 px JPEG), never copies photos.
- CSV: `file,name_pl,name_ru,brand,ms,input_tokens,output_tokens,cost_usd,image_bytes,error`.
- `--budget-usd` is required; the run stops before a call could cross it (next call assumed $0.002 until the first answer, then the most expensive call so far; failed calls are counted as full calls).
- Expected cost: ~1.2–1.8k input tokens per photo on Haiku 5.5 ≈ $0.0002 per photo; 20 photos well under $0.01.
