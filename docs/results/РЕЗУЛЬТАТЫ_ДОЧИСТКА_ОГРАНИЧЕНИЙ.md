## Done

1. **Feed «Нужно проверить» segment at 375 px** (`PurchaseFeed.module.css`):
   labels never wrap inside a pill (`white-space: nowrap`), side padding
   0.6 → 0.55rem, gap 0.4 → 0.35rem. At 375 px all three segments are on one
   row, 44 px tall (before, «Нужно проверить» took two lines and the row was 57 px).
   If the text does not fit (320 px, larger text) a whole segment moves to the
   next row instead of breaking mid-label. No horizontal scroll at 320/375 px.
2. **Purchase editor returns to the queue after save** (`PurchaseDetailPage.tsx`,
   `ReviewQueuePage.tsx`): «Исправить покупку», «Выбрать товар»/«Другой товар»
   and «Открыть покупку» in the queue pass the same router state as receipt
   links (`reviewQueueReturnState`). After «Сохранить исправления» the editor
   navigates to that `/needs-attention?…` address (validated by
   `reviewQueueReturnPath`; anything else is ignored). The state is kept across
   «Исправить»/«Отменить» switches, so view → edit → save also goes back.
   Cancel stays on the purchase; without the state the old behaviour (saved
   notice on the purchase page) is unchanged. The queue is already invalidated on save.
3. **MCP `list_review_queue`** (`Mcp/ReviewQueueTools.cs`): optional
   `categoryId` and `uncategorized`, sent as `ReviewQueueFilter` exactly like
   `GET /api/review-queue`. Unknown category and category + uncategorized come
   back as tool errors (`isError`). Description updated.
4. **Storybook**: `Analytics/Page › HistoryOutdatedMobile` and
   `HistoryOutdatedEnglish` (history list + the «older version» notice).
5. **en quotes**: `categories.deleteConfirm` now `Delete “{{name}}”?`. No other
   en string (i18n en block, `helpEn`, runtime strings in `.ts/.tsx`) uses «».
6. **AuthGate stale-token nit**: inside the 30 s recovery window, 401s from
   requests that left with an older token now trigger at most one
   `invalidateQueries` per recovery (flag `staleRetried`, reset on each
   successful refresh); before, every such 401 refetched all queries again.
   Security is unchanged: the fresh token being rejected still ends the
   session, and nothing is retried that the server would accept otherwise.

Help: «Нужно проверить» and «Исправление покупки» topics (ru + en) now say
that saving a purchase opened from the queue returns there with the same
filters. `КОНТЕКСТ_ПРОЕКТА.md`: MCP note lists the new arguments.
