# Results: plan #1, stage 1.1 — every receipt line becomes a product

## What was built
- Grey-zone match (old "pending") now creates a product flagged NeedsReview
  («проверить») with an AutoCreated alias and up to 5 stored candidates
  (`product_review_candidates`); later lines with the same wording reuse it.
- `Product.Origin` (receipt / manual / barcode), `NeedsReview`, `ReviewReason`.
- API: `POST /api/products`, `PUT /api/products/{id}/name`,
  `POST /api/products/{id}/merge-into/{targetId}` (one transaction: lines,
  impressions, aliases, audit, tags, candidates, classification),
  `POST /api/products/{id}/confirm-distinct`; catalog filters `needsReview`,
  `excludeProductId`. Concurrent DB refusals (incl. PG deadlock) → 409.
- Migration `AddProductReviewFlag` (SQLite `20261016150110`, PG
  `20261016150254`): pending matches → flagged products, grouped by wording
  across stores (owner), alias per store, candidate union top 5; pending tables
  dropped. `Down` restores schema only.
- Review queue: kind `productNeedsReview`; a flagged product is ONE item even
  with no / AI-suggested category (owner); action texts «Тот же товар или
  новый?», «Новый товар: проверьте и выберите категорию.», «…подтвердите
  категорию «X».».
- Web: «проверить» chip, filter `/products?review=1`, tappable count, queue
  card «Похожие товары» (merge confirm, «Это другой товар»), product card banner
  on top + «Объединить с…», LineReview «Связано с …» / «Изменить товар», line
  picker shows candidates, scanner «Новый товар» (OFF prefill). Help ru/en.
- Fix: purchase edit with a rated line no longer 500s (EF cycle on the
  (PurchaseDraftId, Position) index); two-step save in one transaction, impressions
  follow their line by `LineId`.

## Known limitations
- If one store already had an alias for a wording, another store's pending line
  for it still becomes a new flagged product (recoverable by merge).
- Relinking a flagged line leaves its product with 0 purchases in the queue.
- Any DB refusal inside merge/rename shows as 409 «changed at the same time».
- Confirming the category on a flagged card keeps the card (product still flagged).
