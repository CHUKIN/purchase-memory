# Results: receipt line highlight on the photo (2026-10-14)

Frontend only. No backend, API or DB changes; no migrations.

## What was done
- New `src/PurchaseMemory.Web/src/features/receipt-photo/`:
  - `photoBox.ts` — shared box geometry: `isUsableBox`, `padBox` (moved out of `IssueReview.tsx`), `contextWindow` (line + a few neighbouring rows), `relativeTo`, `imageOffset`, and the `ReceiptPhoto { url, croppable }` type (`IssueReviewPhoto` is now an alias).
  - `ReceiptPhotoFocus.tsx` — a strip of the photo around the line with the line outlined (the rest dimmed); the outline appears only after the photo's natural size is known, so it is never misplaced. Falls back to the whole photo with no outline.
  - `ReceiptLineViewer.tsx` — a sheet with the photo fragment and the line's name, `qty unit × price` and sum. Two modes from the setting:
    - **tap** («Нажатие», default): shows the one tapped line; title «Строка N на фото».
    - **swipe** («Пролистывание»): starts at the tapped line; horizontal swipe on the photo (pointer events, `touch-action: pan-y`, ≥40 px and mostly horizontal), «Предыдущая»/«Следующая» buttons (aria-labels «Предыдущая строка»/«Следующая строка», disabled at the ends), ArrowLeft/ArrowRight; live status «Строка N из M».
  - `lineLocatorMode.ts` — per-device preference in `localStorage` key `purchase-memory.line-locator-mode` (`useSyncExternalStore`, in-memory fallback if storage throws, unknown value → `tap`).
- Setting: «Ещё» on Главная → Настройки → «Строки чека на фото» (IonSegment «Нажатие» / «Пролистывание» + a hint for the chosen mode). `settings.open` aria-label is now «Ещё: подсказки, настройки, выход».
- Screens:
  - **Purchase detail (view)**: with a receipt photo, each product line's name/status is one button (the «Оценить» impression button stays outside it, no nested controls); discount rows become tappable rows. Footnote «Нажмите на строку…» + HelpLink to the new topic. No photo → lines stay plain, no receipt request.
  - **Purchase editor** and **receipt full editor** (`LinesEditor`): the line sheet gets «Показать на фото», which opens the viewer over the sheet (tapping a line there already means editing).
  - Not added: issue review (already shows a fragment per issue, now via the shared helpers), saved receipt page (no line list), review queue, feed.
- Help: new topic `receipt-lines-photo` «Строки чека на фото» (group history, ru+en); one «see» line added to `review-save`.
- `formatQuantity` moved to `features/purchases/money.ts` (shared by `LinesEditor` and the viewer).

## Coordinates and fallbacks
- Boxes are fractions 0..1 of one image, x/y = top-left (backend `BoundingBox.TryCreate` validates; UI re-checks with `isUsableBox`).
- Multi-photo receipts: recognition does not say which part a box is on, so `croppable = false` → first photo whole, no outline, note «Чек снят на нескольких фото…». Purchase detail learns the part count via `GET /api/receipts/{id}` (`usePurchaseReceiptPhoto`, shared query key `["receipts", id]`); until it answers or if it fails, nothing is outlined.
- Line without a usable box: whole photo, no outline, note «Место этой строки на фото не найдено — показан весь чек.»; still part of the swipe walk.
- Photo loading / failed: «Загружаем фото чека…» / alert «Фото чека не загрузилось.»

## Review follow-up (review 1: NOT READY)
- MAJOR: `.pm-locator-frame` had `max-height: 55vh`, which squashed the strip on short screens and put the outline on the wrong row. Now no max-height; once the photo ratio is known the strip gets `aspect-ratio` + `width: min(100%, calc(55vh * ratio))` (`frameStyle` in `ReceiptPhotoFocus.tsx`), so it narrows instead. Measured in Storybook: 812×375 strip 604×206 px (ratio kept, 206.24 vs 206.25 expected), outline vs line edges off by <0.02 px; 375×812 same.
- Nav row: status `nowrap` + `flex: none`, buttons shrink (4 px padding); below 360 px the button words hide (aria-labels stay). At 375 px: nav 359 px, no overflow, status one line.
- Focus: when «Следующая»/«Предыдущая» becomes disabled at an end while focused, focus moves to the position status (`tabIndex=-1`) inside the sheet (checked in real Ionic too).
- Live region now announces «Строка N из M: <name>, <sum>» (visually hidden; visible text stays «Строка N из M»).
- Tappable discount rows on purchase detail get the hidden «Показать на фото» suffix.
- Help «see» line fixed (ru+en): line number is in the title in tap mode, between the buttons in swipe mode; in editors the viewer shows unsaved edits.
- The viewer keeps the last line's content while the sheet dismisses (no empty sheet / «Строка 1» title flash); each opening still starts at the tapped line.
- `.pm-line-name` colour uses `var(--ion-text-color, #000)`.
- New story `Landscape` (phone rotated). Tests +5: ratio helper, focus at end, announcement text, reopen restarts at tapped line, discount row name.

## Known limitations
- Analysis uses the original upload; the display copy has EXIF orientation applied. A photo with a non-default EXIF orientation could get boxes in a rotated frame (not seen in test data, not verified).
- Multi-photo receipts never highlight (needs a photo index from recognition).
- No pinch-zoom; fragment size is fixed (line + ~2 rows each side).
- Swipe mode only walks and shows; no per-line «confirm» step (owner's "max" wizard idea).
- Not checked on a real iPhone / iOS Simulator; stacked sheets (line sheet → viewer) checked only in unit tests.
