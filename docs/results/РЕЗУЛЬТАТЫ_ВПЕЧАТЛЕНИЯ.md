# Результаты этапа «Впечатления о товаре»

Дата: 26.09.2026. Статус: реализовано, ждёт независимого review.

## Что сделано

Каждый участник может оценить купленную позицию по шкале «не нравится /
средне / нравится», добавить заметку и фото. Оценка необязательна и никак не
мешает сохранению покупки.

- **Модель данных.** Новая сущность `ProductImpression` (таблица
  `product_impressions`): автор (Supabase `sub` + email), оценка, заметка до
  2000 символов, фото, время. Привязка — к строке покупки (`PurchaseItemId`),
  через неё к товару, магазину, дате и цене. Дополнительно хранятся
  `PurchaseId`, название строки и товар на момент оценки — чтобы впечатление не
  потерялось, если строку позже удалят правкой.
- **История только дописывается.** Изменилось мнение — это новое впечатление;
  старое не переписывается. Редактирования нет. Своё впечатление можно
  **удалить** (например, нажали не ту кнопку), но это мягкое удаление: строка и
  фото остаются в базе с `DeletedAt`, из списков впечатление пропадает. Чужое
  удалить нельзя — сервер отвечает 403. Почему так: продуктовая сессия прямо
  говорит «оценка и заметка не перезаписываются навсегда», поэтому правка
  исключена, а мягкое удаление ничего не стирает.
- **Правка покупки не теряет впечатления.** Редактор покупки заменяет все
  строки новыми. Перед сохранением репозиторий переносит впечатления на новую
  строку с тем же названием (ближайшая позиция, одна новая строка — одно
  старое место). Если строку удалили совсем, впечатление остаётся у покупки и
  товара, но без цены. Внешний ключ `ON DELETE SET NULL` — последняя
  страховка.
- **Фото впечатления** — отдельно от фото товара и чека. Хранится в том же
  хранилище (локальная папка или S3) под префиксом
  `impressions/{id}/photo.jpg`. Используется тот же конвейер, что для копии
  чека (`ReceiptImageCompressor`): EXIF-поворот, ≤ 2400 px, JPEG 82, без
  EXIF/GPS, лимит 15 МБ, проверка JPEG/PNG/WebP. Оригинал не сохраняется —
  значит, геопозиция из телефона вообще не попадает в хранилище.
- **API** (всё за политикой «одобренный пользователь», автор берётся только из
  токена):
  - `POST /api/impressions` — multipart: `purchaseItemId`, `rating`
    (`dislike`/`neutral`/`like`), `note`, `photo`; 201;
  - `DELETE /api/impressions/{id}` — только своё; 204 / 403 / 404;
  - `GET /api/impressions/{id}/photo`;
  - `GET /api/products/{id}/impressions`, `GET /api/purchases/{id}/impressions`,
    `GET /api/purchase-items/{id}/impressions`;
  - `GET /api/products/{id}/rateable-lines` — покупки товара для выбора «какую
    оцениваю»;
  - `GET /api/impressions/unrated?days=30&limit=8` — недавние неоценённые
    строки текущего пользователя (по одной на товар; товар не предлагается,
    если его уже оценили после этой покупки).
  - В ответе покупки `GET /api/purchases/{id}` у строки появилось поле `id`.
- **MCP:** только чтение — `list_product_impressions` (впечатления о товаре).
  Создание через MCP не добавлялось: там нет надёжного автора. В аналитику
  впечатления не включались.
- **Миграции:** `20260926210635_AddProductImpressions` (SQLite) и
  `20260926210656_AddProductImpressions` (Postgres, схема `purchase_memory`).
  Только новая таблица и индексы, существующие данные не трогаются.
- **Интерфейс** (ru/en):
  - на странице покупки у каждой товарной строки — сводка «Вы: Нравится ·
    boris@…: Средне» и кнопка «Оценить» с формой;
  - на странице товара — блок «Впечатления»: выбор покупки (магазин · дата ·
    цена), оценка, заметка, фото; история отдельно по каждому человеку («Вы»
    первым); таблица «Сравнение по магазинам» (сколько каких оценок и последняя
    оценка каждого);
  - на главной — блок «Оценить недавнее» с оценкой в одно нажатие; если
    оценивать нечего или запрос не удался, блока просто нет.
  - Оценка — нативная группа радиокнопок (`fieldset` + `legend`), работает
    стрелками, у каждой группы понятное имя.

## Известные ограничения

- Нет «Напомнить позже» и недельного дайджеста — только блок на главной.
- Перенос при правке — по совпадению названия строки. Если в правке строку
  переименовать, впечатление останется у покупки и товара, но без цены.
- Удалённые впечатления и их фото хранятся бессрочно; интерфейса
  «восстановить» нет.
- Автор показывается по email; отдельных имён участников в системе пока нет.
- `list_product_impressions` в MCP всегда отдаёт `isMine = false`.
- Таблица сравнения на узком экране прокручивается горизонтально.

## Следующий кандидатный шаг

«Напомнить позже» / скрытие позиции из «Оценить недавнее», фильтр каталога
«понравилось», затем раздел «Подсказки».

## Для подсказок

- Оценивать покупки необязательно — сделать это можно в любой момент позже.
- На главной есть блок «Оценить недавнее»: одно нажатие — «Не нравится»,
  «Средне» или «Нравится». Оценённая позиция из списка пропадает.
- На странице покупки у каждой строки есть кнопка «Оценить»: там же можно
  добавить заметку и фото (например, как товар выглядит внутри).
- На странице товара в блоке «Впечатления» выберите, какую покупку оцениваете
  (магазин, дата, цена), — и мнение привяжется именно к ней.
- У каждого участника своя история впечатлений. Если мнение изменилось,
  просто оставьте новое — старое сохранится в истории.
- «Сравнение по магазинам» показывает, где товар понравился, а где нет.
- Своё впечатление можно удалить; чужое — нельзя.
