# Деплой: что нужно сделать вам, чтобы агент мог выложить приложение

Дата: 05.10.2026. Это пункт 5 плана деплоя (`ПЛАН_ОБЛАКО_ФОТО_ИЛИ_ТЕКСТ.md`).
Код к нему уже готов: Postgres, хранилище фото S3 и вход через Supabase сделаны
и проверены. Нет только самого хостинга.

## Коротко: какая схема предлагается

| Что | Где | Цена |
|---|---|---|
| Приложение (Docker-контейнер, .NET + сайт) | **Render**, бесплатный Web Service | $0 |
| Образ контейнера | **GitHub Container Registry** (закрытый пакет на вашем GitHub `CHUKIN`) | $0 |
| База и фото | **Supabase** Postgres + Storage | $0 |
| Вход | **Supabase Auth** (email-ссылка, Google) | $0 |
| Распознавание чеков, категории, вопросы | **OpenAI** | ≈ $0.02 за чек, по факту |

Почему Render:
- бесплатно;
- есть официальный MCP-сервер, через который агент создаёт сервис, задаёт
  несекретные настройки, запускает деплой и читает логи;
- принимает готовый Docker-образ, поэтому проект не обязательно превращать в
  git-репозиторий.

Минусы бесплатного Render, о которых надо знать заранее:
- **Засыпание.** После 15 минут без запросов сервис засыпает. Первое открытие
  после этого занимает 30–60 секунд, дальше всё работает быстро. Если это
  раздражает, тариф Starter стоит $7 в месяц и не засыпает. Переключить можно
  потом одной кнопкой.
- **Ресурсы.** 512 МБ памяти и 0.1 CPU. Для двух человек достаточно, но
  обработка фото будет медленнее, чем на Mac.
- **Трафик.** 5 ГБ в месяц. Сжатые фото весят сотни килобайт, так что с запасом.

**Чего не делать:** у вас на Mac `az` (Azure) залогинен под рабочей почтой
adanto. Для личного приложения его не используем.

## Что делаете вы (по шагам)

Ни один ключ **не присылайте в чат**. Секреты вы вставляете сами: в `~/.zshrc`,
в панель Render или в менеджер паролей. Агент видит только, есть ли значение
и какой оно длины.

### Шаг 1. OpenAI: новый ключ и лимит расходов (≈ 5 минут)

Текущий ключ из `~/.zshrc` OpenAI отклоняет (ошибка 401), поэтому нужен новый.

1. Откройте https://platform.openai.com → **API keys** → **Create new secret
   key**. Название: `purchase-memory`.
2. Скопируйте ключ в менеджер паролей и замените строку в `~/.zshrc`:
   ```bash
   export OPENAI_API_KEY="sk-..."
   ```
3. Задайте лимит расходов: **Settings → Limits → Budget**, например $10 в
   месяц. Тогда случайно потратить больше не получится.
4. Старый ключ в том же списке нажмите **Revoke**.

Тот же ключ потом вставите на Render (шаг 4).

### Шаг 2. Supabase: проект, вход, база, фото (≈ 30 минут)

Всё уже расписано по пунктам, идите по двум инструкциям подряд:

1. `docs/SUPABASE_AUTH_SETUP.md`, разделы 1–4 и 6–7: проект, таблица
   `app_users` (SQL скопировать и выполнить), вход по email, при желании Google.
   Регион выбирайте **Central EU (Frankfurt)**: это ближе всего к Польше.
2. `docs/SUPABASE_БАЗА_И_ФОТО.md`, разделы 1–3: строка подключения (**Session
   pooler**), закрытый бакет `receipts`, S3-ключи.

Раздел 5 «Адреса возврата» сделаете после шага 5, когда будет известен адрес
приложения.

Запишите в менеджер паролей:

| Значение | Секрет? |
|---|---|
| Project URL `https://<ref>.supabase.co` | нет |
| Publishable key `sb_publishable_…` | нет |
| Строка подключения Postgres (с паролем БД) | **да** |
| S3 Endpoint, Region | нет |
| S3 Access key ID + Secret access key | **да** |

Ключ `sb_secret_…` / `service_role` **не нужен**, не копируйте его никуда.

На бесплатном плане Supabase ставит проект на паузу примерно после недели без
запросов. При обычном использовании этого не будет, а если случится, проект
снова включается кнопкой **Restore** в панели.

### Шаг 3. Render: аккаунт и ключ для MCP (≈ 10 минут)

1. Зарегистрируйтесь на https://render.com (**Get Started** → можно через
   GitHub). Тариф — **Hobby (free)**. Карта для бесплатного сервиса не нужна;
   если Render её попросит, сообщите, решим.
2. **Account Settings → API Keys → Create API Key**. Ключ даёт доступ ко всему
   аккаунту Render, поэтому храните его как пароль.
3. Добавьте ключ в `~/.zshrc`:
   ```bash
   export RENDER_API_KEY="rnd_..."
   ```
4. Подключите MCP-сервер Render к Claude Code. Откройте **новый** терминал,
   чтобы подхватился `~/.zshrc`, и выполните команду сами:
   ```bash
   claude mcp add --transport http render https://mcp.render.com/mcp --header "Authorization: Bearer $RENDER_API_KEY"
   ```
5. Перезапустите сессию Claude Code. Агент проверит подключение командой
   «показать список сервисов». Сейчас список пуст, и это нормально.

### Шаг 4. GitHub: разрешить агенту выкладывать образ (≈ 3 минуты)

GitHub CLI у вас уже залогинен (аккаунт `CHUKIN`). Нужно только добавить ему
право публиковать пакеты. Выполните сами (откроется браузер):

```bash
gh auth refresh -s write:packages,read:packages
```

Затем, чтобы Render мог скачивать **закрытый** образ:

1. GitHub → **Settings → Developer settings → Personal access tokens →
   Tokens (classic) → Generate new token (classic)**.
   - Note: `render-pull`;
   - срок: 1 год;
   - галочка **только** `read:packages`.
2. Render → **Workspace Settings → Registry Credentials → Add**:
   - Registry: **GitHub**;
   - Username: `CHUKIN`;
   - Token: этот токен.

   Название: `ghcr-chukin`. Агенту токен не нужен, ему нужно только название.

### Шаг 5. Секреты на Render (после того как агент создаст сервис)

Агент создаст сервис `purchase-memory` и сам впишет все **несекретные**
настройки:
- `Database__Provider=Postgres`;
- `Storage__Provider=S3`;
- адреса Supabase;
- `ASPNETCORE_ENVIRONMENT=Production`;
- и т. д.

Секреты вставляете вы: Render → сервис → **Environment** → **Add Environment
Variable**.

| Имя | Значение |
|---|---|
| `ConnectionStrings__Postgres` | строка Session pooler из шага 2 |
| `Storage__S3__AccessKeyId` | из шага 2 |
| `Storage__S3__SecretAccessKey` | из шага 2 |
| `OPENAI_API_KEY` | из шага 1 |

Полный список переменных (секретных и нет), порт и путь проверки здоровья —
в `docs/ДЕПЛОЙ_RENDER.md`.

После этого нажмите **Save, rebuild and deploy** или скажите агенту
«секреты вписаны».

### Шаг 6. Адрес приложения в Supabase (≈ 2 минуты)

Приложение получит адрес вида `https://purchase-memory-xxxx.onrender.com`.
Откройте Supabase → **Authentication → URL Configuration** и сделайте, как в
`docs/SUPABASE_AUTH_SETUP.md`, раздел 5:
- **Site URL**: этот адрес;
- **Redirect URLs**: этот адрес.

Свой домен (например `pokupki.ваш-домен.pl`) можно добавить позже. Это
необязательно, `onrender.com` уже даёт HTTPS.

### Необязательно: Supabase MCP

Без него можно обойтись: всё в Supabase вы делаете сами по инструкциям выше. С
ним агент сможет сам проверить, что таблица `app_users`, хук и бакет настроены
правильно, и посмотреть логи входа. Подключение через вход в браузере, ключ не
нужен:

```bash
claude mcp add --transport http supabase "https://mcp.supabase.com/mcp?project_ref=<ref>&read_only=true"
```

`read_only=true` разрешает агенту только смотреть, но не менять. После команды
выполните `/mcp` в интерактивном терминале `claude` и войдите в Supabase.

## Что потом делает агент (отдельный этап, после вашего «да»)

1. Небольшие правки для хостинга (сделано 06.10.2026, см. `РЕЗУЛЬТАТЫ_ХОСТИНГ.md`
   и `docs/ДЕПЛОЙ_RENDER.md`; новая версия образа — `./scripts/publish-image.sh`):
   - приложение слушает порт из переменной `PORT` (так требует Render);
   - проверка здоровья `/health`;
   - выключен локальный Ollama-адрес по умолчанию;
   - сборка образа под `linux/amd64`.
2. Собирает образ, выкладывает в `ghcr.io/chukin/purchase-memory` (закрытый).
3. Через Render MCP создаёт сервис из образа, задаёт несекретные переменные и
   просит вас вписать секреты (шаг 5).
4. Деплоит, читает логи, проверяет:
   - миграции применились в Supabase;
   - сайт открывается.
5. Проверка защиты **реальными попытками обхода**:
   - запросы без токена и с поддельным токеном;
   - убедиться, что `Auth__DevelopmentBypass` выключен;
   - убедиться, что фото без входа не отдаются.
6. Отчёт `РЕЗУЛЬТАТЫ_ХОСТИНГ.md` и инструкция «как обновить приложение»: собрать
   образ и нажать Deploy, это агент сможет делать по вашей просьбе.

Отдельные следующие этапы:
- **Пункт 6 — перенос ваших данных** (`data/purchases.db` и фото) в Supabase.
  Сначала на копии, с проверкой и вашим отдельным согласием. До этого
  приложение в облаке будет с пустой базой, а локальная остаётся как есть.
- **Пункт 7** — проверка на iPhone (PWA «На экран Домой»).

## Сводка: что где лежит

| Что | Кто вводит | Где хранится |
|---|---|---|
| `OPENAI_API_KEY` | вы | менеджер паролей, `~/.zshrc`, Render (секрет) |
| `RENDER_API_KEY` | вы | менеджер паролей, `~/.zshrc`, настройка MCP |
| GitHub `write:packages` | вы (`gh auth refresh`) | связка ключей macOS |
| GitHub-токен `read:packages` | вы | только Render Registry Credentials |
| Supabase URL + publishable key | вы или агент (не секрет) | Render env |
| Строка Postgres, S3-ключи | вы | менеджер паролей, Render (секрет) |
| Supabase MCP | вход в браузере | ключа нет |

Если какой-то ключ попал в чат, скриншот или файл, отзовите его по
`docs/ПЕРЕМЕННЫЕ_И_СЕКРЕТЫ.md`, раздел «Что делать, если ключ попал куда не надо».
