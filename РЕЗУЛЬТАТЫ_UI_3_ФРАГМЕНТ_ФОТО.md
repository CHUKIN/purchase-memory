# Purchase Memory — результаты UI-3, срез «фрагмент фото чека в карточке неточности»

Дата реализации: 30 августа 2026
Статус: реализован третий срез UI-3 (после «ленты+фильтров» и «issue-review как
экрана по умолчанию»). **UI-3 целиком не завершён**: audit trail применённых
исправлений остаётся будущей работой, Apple-пайплайн координаты пока не
возвращает.

## Результат

Карточка неточности больше не ограничена текстом. Если распознавание вернуло
координаты значения на фотографии, карточка показывает **фрагмент** фото — ровно
ту строку чека, о которой идёт речь. Если координат нет или они не прошли
валидацию — показывается фотография целиком; если фотографии нет — карточка
остаётся прежней текстовой. Текст (распознанное значение и предложение) никуда
не делся: фрагмент его дополняет, а не заменяет.

Кроп чисто визуальный: бэкенд не режет и не хранит второе изображение.
Контейнер с `overflow: hidden` показывает нужный участок увеличенной копии
исходного полноразмерного файла.

Дополнительно закрыт `npm audit`: 3 транзитивные уязвимости (nanoid/postcss
через vite, undici через jsdom) устранены `npm audit fix` — обновился только
`package-lock.json`, прямые зависимости и их версии в `package.json` не
изменились. `npm audit` теперь сообщает 0 уязвимостей.

## Контракт распознавания: schema v2

Добавлена необязательная привязка значения к месту на фото:

- `items[].boundingBox` — рамка строки позиции;
- `receiptTotalBoundingBox` — рамка напечатанного итога.

Рамка — `{x, y, width, height}` в **относительных долях** размера изображения
(0.0–1.0), а не в пикселях: снимки с разных устройств имеют разное разрешение.
Версии подняты до `receipt.extract.prompt.v2` / `receipt.extract.schema.v2`,
дельта описана в `docs/contracts/receipt-extract-v2.md`, нормативная schema —
`docs/contracts/receipt-extract-result-v2.schema.json`. Промпт явно требует
возвращать `null` при неуверенности: «неверная рамка хуже отсутствующей».

## Валидация координат

Единственное место — `PurchaseMemory.Domain.Receipts.BoundingBox.TryCreate`.
Любое нарушение молча даёт `null` (распознанные суммы при этом сохраняются, чек
не отклоняется):

- отсутствует любая из четырёх координат, или значение не число / не конечное;
- отрицательные `x`/`y`, выход рамки за пределы кадра;
- `width` < 0.01 или `height` < 0.002 — нечитаемая полоска;
- площадь > 0.9 кадра — рамка «на весь чек» ничего не подсказывает.

Допуск на округление модели — 0.005 по границе. Ту же валидацию проходят
координаты, которые PWA присылает обратно в review-запросе, поэтому клиент не
может протолкнуть мусорный кроп в базу.

## Поддержка провайдерами

| Провайдер | bbox | Комментарий |
|---|---|---|
| Ollama (structured vision) | да, проверено вживую | JSON Schema уходит в `format` без изменений; `qwen3.5:4b` вернул рамки для всех позиций и итога |
| OpenAI (Responses structured output) | технически поддержан | Схема (включая `$defs`/`$ref` и nullable-объект) уходит в strict json_schema тем же путём; вживую не проверялось — `OPENAI_API_KEY` в этой среде нет |
| Apple (sidecar) | нет | Вне скоупа среза: у Apple Vision другой источник координат (построчный OCR). Поле всегда `null`, ничего не ломается |

Ни один провайдер не обязан возвращать рамку: это best-effort с graceful
fallback на всех уровнях.

## Хранение

Координаты стали частью снимка чека, а не эфемерным результатом одного вызова
модели: миграция `20260829234902_AddRecognitionBoundingBoxes` добавляет по
четыре nullable-колонки в `receipt_capture_items` и `receipt_captures` (EF owned
type, аддитивно, существующие строки остаются валидными с `NULL`).

Покупка (`purchase_drafts`) координаты **не** хранит: в ленте покупок фотографии
нет, поэтому кроп там нечем показать. Поле `boundingBox` в issue покупки
присутствует в JSON и всегда `null` — контракт issue един для обеих
поверхностей.

Рамки переживают редактирование: PWA возвращает их в review-запросе, и они
проходят валидацию заново. Без этого первое же сохранение стирало бы привязку.

## Frontend

- `IssueReview` получил необязательный проп `photo: { url, croppable }`.
- Кроп: контейнер с `overflow: hidden`, внутри — тот же полноразмерный `<img>`,
  масштабированный до `100 / width` процентов и сдвинутый отрицательными
  `left`/`top`. Соотношение сторон рамки вычисляется после `onLoad` по
  натуральным размерам снимка, поэтому фрагмент не растягивается.
- Рамка расширяется на ~2% по горизонтали и ~1.5% по вертикали, чтобы строка не
  упиралась в края кадра.
- Многостраничный чек (`imageParts.length > 1`) не кропается: рамка описывает
  одно изображение, и понять, какое именно, нельзя. Показывается первое фото
  целиком.
- Доступность: у фрагмента и у полного фото есть отдельные alt-тексты (ru/en),
  вся информация карточки по-прежнему доступна текстом. Анимаций не добавлено,
  глобальное правило `prefers-reduced-motion` не затронуто.
- Новых npm-зависимостей нет.

## Как проверить вручную

```bash
# ВНИМАНИЕ: изолированная база, data/purchases.db не трогаем.
SCRATCH=$(mktemp -d)
./scripts/dotnet.sh run --project src/PurchaseMemory.Api --urls http://127.0.0.1:5199 \
  --Paths:DataDirectory=$SCRATCH --Paths:LogDirectory=$SCRATCH/logs \
  --ReceiptRecognition:Pipeline=ollama --ReceiptRecognition:Mode=Vision

curl -s -X POST http://127.0.0.1:5199/api/receipts -F "file=@test-data/receipts/02-sklep-u-asi.jpg"
curl -s -X POST http://127.0.0.1:5199/api/receipts/<id>/process
curl -s http://127.0.0.1:5199/api/receipts/<id>   # snapshot.items[].boundingBox
```

Проверка отсечения мусора — прислать в `PUT /api/receipts/<id>/review` заведомо
некорректные рамки (`width: 9.9`, `{0,0,1,1}`) рядом с корректной: в ответе
некорректные становятся `null`, корректная сохраняется и попадает в `issues[]`.

Storybook: истории `IssueReview/Production/PhotoFragment` и `PhotoFallback`
показывают оба состояния на встроенной SVG-подделке чека, без запущенного API.

## Известные ограничения

- Рамку не гарантирует ни одна модель. Это best-effort: карточка обязана быть
  полезной и без фрагмента.
- Локальная 4b-модель ставит рамки приблизительно: строка «итог» и строка
  «Mleko» получили близкие координаты по вертикали. Валидация отсекает мусор, но
  не может проверить, что рамка указывает на *правильную* строку.
- Многостраничные чеки без кропа (см. выше).
- Apple-пайплайн координаты не возвращает.
- Покупки в ленте координат не хранят.
- Audit trail применённых исправлений по-прежнему не сделан.
