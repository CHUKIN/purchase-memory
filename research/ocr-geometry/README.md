# Черновики: OCR + геометрия + текстовая модель

**Это не продакшн-код.** Исследовательские скрипты от 21 сентября 2026,
на которых получены замеры из `ПЛАН_КОНВЕЙЕР_OCR_ГЕОМЕТРИЯ.md`. Сложены сюда,
чтобы при реализации этапов не восстанавливать логику по описанию.
В сборку проекта не входят, тестами не покрыты, на стиль репозитория
не равняются.

## Конвейер

```
1.jpg ──▶ ocr_geom.swift ──▶ frag_N.json ──▶ deskew.py ──▶ rows_N.json ──▶ parse.py ──▶ JSON чека ──▶ reconcile.py
          Apple Vision OCR    фрагменты      подбор        строки         LLM            арифметическая
          с координатами      + координаты   наклона                                     сверка
```

## Файлы

| файл | что делает |
|---|---|
| `drafts/ocr_geom.swift` | Vision OCR → фрагменты с координатами в JSON, без группировки. Координаты нормированы в 0..1000, ось Y перевёрнута (0 = верх чека) |
| `drafts/ocr_rows.swift` | тот же OCR, но со **встроенной** сборкой строк по устойчивому якорю — образец для починки `AppleReceiptSidecar.swift` (этап 1) |
| `drafts/deskew.py` | подбор наклона перебором + сборка строк. Ключевая часть |
| `drafts/parse.py` | промпт и вызов модели через `http://127.0.0.1:11434/api/chat` |
| `drafts/reconcile.py` | арифметическая сверка: пересчёт `qty × unitPrice`, сверка с итогом |

## Как запустить

```bash
swiftc -O drafts/ocr_geom.swift -o /tmp/ocr_geom
/tmp/ocr_geom путь/к/чеку.jpg pl-PL > fixtures/frag_4.json

python3 drafts/deskew.py 4                      # → fixtures/rows_4.json
python3 drafts/parse.py qwen3.5:35b 4           # → fixtures/rows_qwen3.5_4.txt
python3 drafts/reconcile.py fixtures/parsed_4_qwen3.5-35b.json
```

Базовый каталог данных — `fixtures/`, переопределяется через `OCR_GEOM_DIR`.
Номер чека (`4`) — просто суффикс имени файла.

## Фикстуры

Данные чека E.Leclerc Ursynów от 18 сентября 2026 — самого плотного из
имеющихся (48 товаров + 5 скидок, итог 423,46). Единственный чек в выборке,
который был сфотографирован с перекосом, поэтому на нём и видно эффект.

| файл | что это |
|---|---|
| `fixtures/frag_4.json` | 190 фрагментов OCR с координатами |
| `fixtures/rows_4.json` | 75 строк после коррекции наклона (`a = -18`) |
| `fixtures/parsed_4_qwen3.5-35b.json` | разбор локальной моделью |
| `fixtures/parsed_4_nemotron-3-ultra.json` | разбор облачной моделью, для сравнения |

`deskew.py` перезаписывает `rows_4.json` — он и так воспроизводится из
`frag_4.json` байт в байт.

## Воспроизводимость

`python3 drafts/deskew.py 4` должен напечатать `наклон a=-18.0, строк=75`,
а `reconcile.py` на любой из двух фикстур — расхождение `+0.58` до пересчёта
и `+0.62` после. Эти числа разобраны в разделах 1.4 и 1.5 плана.
