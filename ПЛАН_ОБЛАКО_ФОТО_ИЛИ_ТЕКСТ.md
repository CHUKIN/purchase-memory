# План: облако Ollama — фото целиком или только текст

Статус: план, код не менялся. Каждый этап — отдельный цикл `AGENTS.md` и отдельное согласие.
Исполняемое задание для агента: `ЗАДАНИЕ_АГЕНТУ_ОБЛАКО_ФОТО_ИЛИ_ТЕКСТ.md`.
Дата: 22.09.2026.

## Цель

Измерить на Mac, какой путь лучше для будущего деплоя на бесплатный Linux-хостинг + iPhone:

- **Вариант A — «фото в облако»:** фото чека → vision-модель Ollama cloud → JSON. Ничего локального.
- **Вариант B — «текст в облако»:** Apple Vision OCR + геометрия (локально на Mac, позже на iPhone) → строки текста → текстовая модель Ollama cloud → JSON.

Решение принимается по цифрам на одних и тех же чеках, а не на глаз.

## Принципы теста

1. **Честное облако.** Запросы идут напрямую на `https://ollama.com/api/chat` с ключом из переменной окружения `OLLAMA_API_KEY`, а не через локальный демон — так, как будет на хостинге. Ключ вводит владелец сам; в репозиторий, конфиг и логи он не попадает.
2. **Одинаковые условия.** A и B используют один промпт разбора и одну JSON-схему; B получает строки из текущего конвейера `apple-ollama`.
3. **Бережём бесплатный лимит.** Сначала «сито» на 5 трудных чеках (плотные, со скидками, с перекосом); модели, проваливающие 3 из 5, дальше не гоняются (как в прошлых прогонах). Полные 20 — только финалистам.
4. **Последовательно**, по одной модели, с замером времени каждого запроса.
5. Учитываем отказы по лимиту (HTTP 429) отдельно — это не ошибка модели.
6. Реальная база `data/purchases.db` не используется ни одним прогоном.

## Метрики (по `score.py` + дополнения)

- чеков, где сумма позиций сходится с итогом в копейку;
- верный итог чека; верный магазин; верная дата;
- точность позиций (название + цена) против `ground_truth.json`;
- обрывы/невалидный JSON;
- время на чек; расход лимита (сколько чеков съедает тариф в неделю);
- объём отправляемых данных (фото vs текст) — для приватности и лимита.
