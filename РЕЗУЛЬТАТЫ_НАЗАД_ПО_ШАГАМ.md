# Results: "Back goes one step"

Level: Обычный. Web only, no backend changes.

## Done

- New mechanism `src/PurchaseMemory.Web/src/design-system/history/historyLayers.ts`:
  `useHistoryLayer(isOpen, onBack)`. While a layer is open it has its own
  history entry: same URL, same router state (`usr`, `key`, `idx + 1`), and a
  `pmLayer: depth` mark. Leaving the entry (browser back, iOS swipe, header
  chevron) calls `onBack`. Closing it on screen steps back over the entry.
  `onBack` can return `false` (or a promise of it) to stay open, and then the
  entry is pushed again. Layers keep their nesting order through
  `HistoryLayerScope`. History steps are queued until their popstate arrives.
  An entry deeper than the open layers (left behind, or after a reload) is
  stepped back over. `main.tsx` settles a reloaded layer entry at startup.
- `useBack` / `BackButton`: the chevron closes the top layer first. The new
  `leaveLayers` option is used by the scan result's «Готово».
- Wired into: `Sheet`, `PickerModal`, `DateField`, `CatalogSearchModal`,
  `BarcodeScanModal`, `PurchaseLineReview` (back saves the edited line first,
  the same as ✕; a failed save keeps it open), the receipt full editor
  (`ReceiptDetailPage`), and the full-screen scan result (`ScanPage`, variant A).
- Receipt save from the full editor now navigates with `replace`, so it leaves
  no dead step.
- Purchase edit mode (`?edit=1`): «Отмена» and «Сохранить» now step back to the
  view when the editor was opened from it (`editFromView` router state).
  Otherwise they replace the URL. Saving back to the queue uses replace.
- Review fixes:
  - Router `replace` on a layer entry (filters chosen in a filter sheet)
    used to drop the layer mark. `history.replaceState` is now wrapped so the
    mark stays. When the layer is left (Готово, swipe, back), the address it
    ended on is carried down to the entry now shown. The carry uses a native
    replace plus a synthetic popstate for the router. Filters stay, and no
    extra step is left.
  - Saving a purchase correction opened from the queue steps back through
    history to the queue entry (`returnIndex`). A replace is the fallback.
  - The chevron in the receipt full editor is named «Назад», not «Главная».
  - A slow async `onBack` (a line save) gets its entry back at once, so a
    second back during the save stays on the screen.
  - «Готово» on a scan result drops the layers without calling `onBack`, so
    the camera does not restart on the way out (`leaveScreenWithLayers`).
  - Re-review: an address is carried only onto the entry its layer was
    pushed over, matched by router key (`baseKey`). A `pushState` not made by
    this module, or a replace onto another path, forgets the noted layer
    entries. An old editor URL can no longer land on a later visit to the
    same purchase.
  - A URL replace during this module's own step back is still recorded and
    carried down.
  - `backFromLayer(otherwise)` runs after pending steps. A chevron tap while a
    layer's entry is still queued closes that layer instead of acting on the
    screen.
- Help: the «‹» item in ru and en now says back goes one step and closes the
  open sheet first.

## Limitations

- Not checked on a real iPhone. Standalone PWAs may have no edge-swipe back.
  Safari's swipe uses the same popstate path.
- Browser «вперёд» onto the entry of a closed layer is undone. The browser does
  not say which direction it moved, so stepping back is always used.
- `history.replaceState` is wrapped once, the first time a layer opens. The
  wrapper only adds the layer mark when the replaced entry is an open layer's
  entry.
- Not history steps: IonAlert and IonActionSheet confirmations (short choices),
  the carousel photo zoom, disclosures (ReviewHistory, AnswerCard), and the
  capture duplicate notice.
